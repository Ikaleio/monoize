## 基礎 URL 與認證

將請求發送到 Monoize 的監聽位址。預設為 `http://localhost:8080`。使用以下任一請求標頭攜帶 API 金鑰：

```bash
Authorization: Bearer sk-...
# 或
x-api-key: sk-...
```

下列每個端點都有 `/api` 前綴別名，例如 `/api/v1/chat/completions`。當用戶端硬編碼了 `/api` 路徑時使用別名。

任何端點都可以到達任何上游類型。例如，用戶端呼叫 `/v1/messages`，而路由透過 `chat_completion` 類型的 Channel 服務該模型。Monoize 在兩個方向上轉換協議。

Chat 路由會保留 OpenRouter 的 `configuration_update` 訊息，包括空內容更新。檔案 data URI 轉成 Messages 文件時會保留 MIME 類型。Messages 串流會保留 `citations_delta` 引用。Responses 內容過濾終止會保留為未完成狀態，不會誤報為長度限制。

Chat 與 Responses 會將支援的 URL 引用轉換為目標格式。無法表示的引用位置僅在原協定中保留。Token logprobs 與對應文字關聯；文字修改後，不再匹配的機率會被捨棄。Responses 失敗終態保留部分輸出、用量和錯誤詳情。Chat 與 Messages 將失敗或取消狀態輸出為錯誤。Messages 保留暫停、壓縮和上下文限制的停止原因。計費包含上游回報的所有壓縮迭代，不會重複計算主生成用量。

協定轉換分別保留 raw 推理、可讀摘要和不透明的回傳載荷。刪除 raw 推理後，不會用摘要恢復它。Messages 的 thinking 文字映射為摘要，signature 保持不透明。無效的串流生命週期和格式錯誤的已知事件會回傳錯誤。完整 Messages 請求和回應拒絕截斷的工具 JSON；原生 max_tokens 串流可保留未完成的參數位元組。

Chat 中具有相同穩定身分的推理片段會累積到同一節點。最終快照只補上尚未傳送的文字後綴，獨立的 detail 保持分離。

工具參數可以即時輸出。工具簽章信封等待工具終態確定後才輸出，簽章始終作為完整的不透明值處理。

Messages 請求會一起轉換帶物件 `input_schema` 的 custom 工具、JSON 物件呼叫參數和關聯結果，並保留 `call_id`。無效的 schema 或參數會傳回錯誤。

Responses 物件包含非 null 的 error 且缺少有效 status 時會傳回錯誤。空物件會被拒絕。沒有錯誤且包含 output 陣列的相容回應仍可省略 status。

## 列出模型

```bash
curl http://localhost:8080/v1/models \
  -H "Authorization: Bearer sk-..."
```

回應以 OpenAI 列表格式返回呼叫金鑰可用的邏輯模型。

## Chat Completions

```bash
curl http://localhost:8080/v1/chat/completions \
  -H "Authorization: Bearer sk-..." \
  -H "Content-Type: application/json" \
  -d '{
    "model": "my-model",
    "messages": [{ "role": "user", "content": "Hello" }],
    "stream": true
  }'
```

設定 `"stream": true` 使用伺服器推送事件。省略或設為 `false` 則返回單一 JSON 回應。

## Responses

```bash
curl http://localhost:8080/v1/responses \
  -H "Authorization: Bearer sk-..." \
  -H "Content-Type: application/json" \
  -d '{
    "model": "my-model",
    "input": "Hello",
    "stream": true
  }'
```

說明：

- 將傳回的 Monoize id 作為 `previous_response_id`，即可透過任意上游協定接續回應。歷史記錄依 API Key 隔離。
- HTTP 歷史預設使用 `store=true`，在目前程序中最多保留 30 分鐘。重新啟動或快取淘汰會移除記錄。
- 設定 `store=false` 可關閉 HTTP 歷史保留。未知或過期的 id 會傳回 `400 previous_response_not_found`。收到此錯誤後，請重新傳送完整歷史。
- 每次請求都應提供目前的 instructions 和控制參數。前一請求的頂層 `instructions` 不會自動繼承。
- `GET /v1/responses` 支援 Codex WebSocket v1 和 v2。v1 傳送 `response.done`，v2 傳送 `response.completed`。`store=false` 不影響連線內接續。
- `GET /v1/codex/responses` 與 `GET /v1/responses` 使用同一個 WebSocket 處理器。`POST /v1/codex/responses` 與 `POST /v1/responses` 使用同一個 HTTP 處理器。兩個新路徑也有 `/api` 別名。
- Responses WebSocket 用戶端可以對 Responses Channel 開啟上游 WebSocket。`POST /v1/responses` 仍使用 HTTP。握手失敗時，同一 attempt 回退到 HTTP SSE。
- `POST /v1/responses/compact` 壓縮一段會話。
- Monoize 將原生 compact 請求體轉發到上游 `POST /v1/responses/compact`。
- 選定 Channel 後，如果該 Channel 對應了 `{model}-openai-compact`，Monoize 把線路模型改成這個兄弟模型。否則送出會話模型。
- 計費使用會話模型的價格。兄弟模型 ID 不需要單獨的價格記錄。

向 Responses 上游轉送請求時，Monoize 保留明確傳入的 `include` 和 `reasoning.summary`。它不會自動加入 `reasoning.encrypted_content` 或預設摘要設定。

## 關閉推理

在 Chat Completions 請求中設定 `"reasoning_effort": "none"`。在 Responses 請求中設定 `"reasoning": { "effort": "none" }`。

Monoize 會向 OpenAI 相容上游保留明確指定的 `none`。如果 Chat 請求保留了原生 `reasoning` 物件，Monoize 會在該物件中寫入 `effort: "none"`，不再傳送頂層簡寫欄位。

如果沒有明確指定 Messages 控制參數，Monoize 會向 Messages 上游傳送 `thinking: { "type": "disabled" }`。Gemini 上游收到 `generationConfig.thinkingConfig.thinkingBudget: 0`。

DeepSeek Chat 請求會直接傳遞推理努力值，不重新映射數值，也不自動產生 `thinking` 控制參數。

省略推理力度會允許上游使用預設值。請選擇支援關閉推理的模型。強制推理的模型無法滿足此請求。

curl http://localhost:8080/v1/messages \

## Gemini 上游

將 Channel 的上游類型設為 `gemini`，即可透過現有端點使用 Gemini。此支援不新增公開的 Gemini HTTP 端點，也不包含 Live API。

Monoize 雙向轉換 `generateContent` 請求、回應和對話歷程。串流回應使用 `streamGenerateContent` SSE。

- 文字、推理、函式呼叫、函式結果和支援的媒體保留順序與識別資訊。思考簽章始終關聯原始 Part。
- 生成控制參數、結構化回應格式、工具和工具選擇轉換為目標協定支援的對應欄位。
- Token logprobs 始終關聯相符的文字。文字變更後會捨棄失效的分數。Gemini 最多允許請求 20 個 top logprobs。
- 可表示的引用和 grounding 來源連結轉換為目標格式。引用範圍保留文字中的位置，包括非 ASCII 文字。
- 文字和推理在完成前持續輸出。需要完整內容的媒體和帶簽章的 Part 可以等到完成後輸出。失敗或截斷的串流傳回錯誤。
- Monoize 優先傳回 index 為 0 的候選回應，否則傳回第一個候選回應。獨立候選回應不會合併。

Gemini 專屬工具、Provider 執行的程式碼和無法轉換的中繼資料僅在 Gemini 內保留。目標協定只接收其能夠表示的功能。

## 圖像

生成：

```bash
curl http://localhost:8080/v1/images/generations \
  -H "Authorization: Bearer sk-..." \
  -H "Content-Type: application/json" \
  -d '{
    "model": "my-image-model",
    "prompt": "A lighthouse at dawn",
    "size": "1024x1024"
  }'
```

使用 `multipart/form-data` 上傳圖片檔案：

```bash
curl http://localhost:8080/v1/images/edits \
  -H "Authorization: Bearer sk-..." \
  -F model="my-image-model" \
  -F prompt="Add a red boat" \
  -F 'image[]=@input.png'
```

加入 `-F mask=@mask.png` 可使用 PNG 遮罩。編輯請求接受 1–16 張來源圖片和最多一個遮罩。

使用 JSON 提交圖片參照：

```bash
curl http://localhost:8080/v1/images/edits \
  -H "Authorization: Bearer sk-..." \
  -H "Content-Type: application/json" \
  -d '{
    "model": "my-image-model",
    "prompt": "Add a red boat",
    "images": [{ "image_url": "https://example.com/input.png" }],
    "mask": { "image_url": "https://example.com/mask.png" }
  }'
```

每個 `images` 項目和選用的 `mask` 物件必須恰好包含一個 `image_url` 或 `file_id`。`image_url` 接受 HTTP(S) URL 或 Base64 資料 URL。檔案 ID 必須能透過所選上游憑證存取。檔案 ID 不會在上游帳號或 Provider 之間轉移檔案。

兩個端點都必須提供 `model` 和 `prompt`。非串流請求的 `n` 仍會拆分為獨立子請求。設定 `stream=true` 和 `n=1` 可接收圖像 SSE 事件。原生 `openai_image` 路由將內嵌圖片以 multipart 傳送。只要任一輸入或遮罩保留 HTTP(S) URL 或檔案參照，該路由就使用 JSON。

設定 `stream=true` 後，Monoize 立即傳送 SSE 保活註解，並在連續 15 秒沒有資料事件時再次傳送。OpenRouter 圖片編輯自動使用非串流上游請求；其他路由收到明確拒絕串流的 HTTP 400 或 422 後，只回退一次。JSON 圖片回應轉換為完成事件，不會偽造預覽圖。計費與日誌仍計為一次串流請求，一般網路錯誤不會觸發此回退。這可以在生成期間維持下游連線，但不會延長上游請求逾時。

對於 Responses 路由，設定 [image_enable_openai_generation_tool](/zh-TW/docs/transforms/image_enable_openai_generation_tool)。請求中的圖像參數優先於變換預設值，遮罩會映射到工具的 `input_image_mask`。圖像 `background` 用於設定工具，與 Responses 的布林值 `background` 不同。Responses 路由會明確拒絕圖像 `style` 和 `response_format="url"`。

圖像回應保留上游回傳的 `quality`、`size`、`background`、`output_format` 和圖像 `model`。上游未回傳的值保持缺省；請求參數不能證明上游的實際執行結果。回傳多張圖像時，只有所有圖像都報告相同值，回應才會包含對應的頂層欄位。圖像串流的完成事件攜帶各自圖像的中繼資料。

## 使用官方 SDK

將官方 SDK 的基礎 URL 指向 Monoize：

```python
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:8080/v1",
    api_key="sk-...",
)
```

```python
import anthropic

client = anthropic.Anthropic(
    base_url="http://localhost:8080",
    api_key="sk-...",
)
```

## 錯誤回應

| HTTP 狀態碼 | 錯誤碼 | 含義 |
| --- | --- | --- |
| `401` | `unauthorized` | API 金鑰缺失、無效、被停用或已過期 |
| `402` | `insufficient_balance` | 使用者或子帳戶餘額不足 |
| `403` | `model_not_allowed` | 金鑰的模型限制拒絕了請求的模型 |
| `403` | `ip_not_allowed` | 用戶端 IP 不在金鑰的 IP 白名單中 |
| `502` | `upstream_error` | 沒有路由服務該模型，或所有符合條件的路由都失敗 |

上游錯誤文字在到達用戶端之前會被遮罩。完整詳情請在[請求日誌](/zh-TW/docs/request-logs)中檢視。

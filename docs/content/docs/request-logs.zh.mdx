## 日志列表

打开侧边栏中的**日志**。Monoize 为每个通过 API 密钥认证的转发请求记录一行。每行显示：

- 逻辑模型、服务的 Provider 和 Channel，以及 API 密钥名称；
- Token 数量：输入、输出、缓存读取、缓存创建和推理 Token；
- 以美元计的费用；
- 状态：`pending`、`success`、`error` 或 `client_gone`；
- 时间指标：总耗时、首字节时间，以及流式请求的每秒 Token 数。

列表通过服务器推送事件（SSE）实时更新。新行自动出现，无需手动刷新。

## 失败的尝试

当一个请求经过多次上游尝试时，该行会按顺序列出每一跳失败记录。每一跳显示 Provider、Channel、上游状态码和错误文本。通过这个列表可以看到哪个 Channel 失败了，以及请求为什么继续前进。

## 请求捕获

捕获功能把每次上游尝试的完整报文保存到磁盘。捕获默认关闭。两个开关控制它：

1. **系统开关。** `super_admin` 在**设置**中启用请求捕获。系统开关关闭时，任何密钥都不会写入捕获文件。
2. **密钥级模式。** 每个 API 密钥设置 `request_capture_mode`：
   - `off`：从不捕获。
   - `capture-all`：捕获每个到达上游的请求。
   - `capture-only-abnormal`：只捕获失败或异常的请求。

捕获适用于以下端点：`POST /v1/responses`、`POST /v1/chat/completions`、`POST /v1/messages`、`POST /v1/images/generations` 和 `POST /v1/images/edits`。

### Image API 与多模态报文

Image API 的每个子请求写入一份捕获。当 `n` 大于 1 时，捕获的请求 ID 带有后缀 `:img:{i}`，其中 `i` 是从 0 开始的子请求序号。

Monoize 把 `multipart/form-data` 请求体保存为结构化 JSON 对象。对象按传输顺序列出每个部分。文本部分记录字段名和文本。文件部分记录字段名、文件名、内容类型、字节长度和 base64 数据。此规则同时适用于接收到的 `POST /v1/images/edits` 请求体和发送给 `openai_image` 上游的 multipart 表单。

捕获按源报文原样保留图像等多模态内容。Monoize 不做脱敏，也不重新编码。

### 保留与轮转

每个 API 密钥设置 `request_capture_retention`：`5m`、`1h`、`24h` 或 `7d`。默认为 `24h`。捕获在该期限后过期。清理任务在进程启动时运行一次，之后每小时运行一次，删除已过期的捕获。

`super_admin` 可以在**设置**中配置 `monoize_request_capture_max_total_bytes`。面板以 MiB 显示该值。当全部捕获的总大小超过上限时，Monoize 从最旧的捕获开始删除，直到总大小不超过上限。设为 `0` 表示不限制。

Monoize 在后台任务中用 zstd 压缩新的捕获文件，同时仍能读取旧版本写入的未压缩文件。

## 捕获查看器

有捕获记录的行会显示捕获标记。点击标记打开查看器。查看器为每次尝试显示：

- **下游请求**：客户端发来的原始请求体；
- **上游请求**：编码后实际发往上游的请求；
- **URP**：经过所有变换后的请求；
- **响应**：非流式的最终结果。对于流式请求，Monoize 显示重建后的完整响应；
- **输出流**：流式请求的原始 SSE 帧，带语法高亮。仅当该次尝试记录了流式帧时才显示此标签页；
- 实际执行的变换链，包括范围和顺序。

当字符串包含图像 data URL 或 base64 图像数据时，查看器在其下方显示内联预览。无法解码的图像数据会收起预览，仅保留文本。

`user` 角色只能查看自己的捕获，且只能看到 API 密钥范围的变换条目。管理员可以查看 `user` 角色账户的捕获。

## 故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 新行没有捕获标记 | 捕获持久化晚于实时行到达 | 等待列表自动刷新，或刷新一次页面 |
| `capture_not_found` | 捕获已过期、已被轮转删除，或你的角色无权查看 | 提高该密钥的捕获保留期，或联系捕获所有者 |
| 某个密钥的行缺失 | 该密钥属于其他用户 | 以密钥所有者或管理员身份登录 |

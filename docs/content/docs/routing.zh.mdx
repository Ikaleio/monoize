## 路由选择

存在有效订阅时，Monoize 在选择 Provider 前，将密钥分组与订阅分组取交集，并保留密钥分组顺序。
请求不能使用交集之外的 Provider。

对每个请求，Monoize 按以下顺序解析路由：

1. **模型重定向。** 先执行 API 密钥规则，再执行全局规则。第一条匹配的规则重写模型名。
2. **Provider 选择。** Monoize 收集满足以下条件的已启用 Provider：至少有一个已启用、权重大于零的 Channel 服务该模型，且分组与密钥分组有交集。分组顺序决定优先顺序；同一分组内按 Provider 优先级排序。
3. **Channel 选择。** 在选中的 Provider 内，Monoize 按权重随机排序候选 Channel。Channel $i$ 被首先尝试的概率为：

```math
P(i) = \frac{w_i}{\sum_{j=1}^{n} w_j}
```

因此权重为 `2` 的 Channel 获得的流量是权重为 `1` 的 Channel 的两倍。

## 重试与回退

Monoize 按嵌套顺序尝试路由：先在一个 Provider 内遍历 Channel，再前进到下一个 Provider。

- 每个 Channel 获得 `channel_max_retries + 1` 次尝试。默认为 1 次尝试，不做 Channel 内重试。
- `channel_retry_interval_ms` 在 Channel 内重试之间插入等待。默认为 `0`。
- `max_retries` 限制整个 Provider 的总尝试次数。
- 一个 Provider 耗尽后，Monoize 继续尝试下一个符合条件的 Provider。
- 所有 Provider 都耗尽后，客户端收到最后一次失败尝试的状态码和错误。参见[错误响应](/zh/docs/endpoints)。
- 最后一次上游返回 `401`、`403` 或 `407` 时，客户端收到 `502`，错误码为 `upstream_error`。没有任何尝试的请求同样返回 `502 upstream_error`。

### 哪些错误会重试同一 Channel

| 错误 | 同 Channel 重试 | 前进到下一路由 |
| --- | --- | --- |
| HTTP `408`、`429`、`5xx` | 是 | 是，Channel 预算耗尽后 |
| 超时、连接被拒绝或重置 | 是 | 是，Channel 预算耗尽后 |
| 其他上游错误（如 `400`、`401`、`404`） | 否 | 是，立即前进 |
| Monoize 自身错误（认证、余额、校验、计费） | 否 | 否；路由终止 |

## 流式保证

Monoize 在第一个上游尝试被接受后发送 SSE 响应头。HTTP 尝试在收到 `2xx` 状态码时被接受。上游 WebSocket 尝试在收到第一个非 Provider 控制事件时被接受。此前的失败返回原生 JSON 错误，而不是 SSE。

发送响应头后，回退继续有效，直到第一个协议数据或错误事件。Monoize 缓冲响应开始事件和 Provider 控制事件（例如 `codex.rate_limits`），直到第一个输出事件。缓冲区最多容纳 256 个事件。SSE 心跳在响应头之后开始，不会结束回退。

如果响应头发送后所有路由都失败，错误会在流中返回，因为 HTTP 状态码已经是 `200`。第一个协议事件之后，Monoize 绝不切换。因此可见的流始终来自同一次生成。

## 熔断器

每个 Provider 有 `circuit_breaker_enabled` 开关。启用时：

- 一个 Channel 在 `window_seconds`（默认 `30`）内出现 `failure_count_threshold`（默认 `3`）次可重试失败后变为不健康。
- 不健康的 Channel 在 `cooldown_seconds`（默认 `60`）内被跳过。由 HTTP `429` 引起的失败使用 `rate_limit_cooldown_seconds`（默认 `15`）。
- 开启 `per_model_circuit_break` 后，健康状态按 `(Channel, 模型)` 组合跟踪，而不是按 Channel。
- 开启主动探测后，Monoize 在后台探测冷却结束的 Channel，达到成功阈值后恢复。

将 Provider 的 `circuit_breaker_enabled` 设为 `false` 可忽略其健康状态。该 Provider 的被动熔断和主动探测随之停止。

## 会话亲和

Monoize 可以优先选择此前服务该会话的 Channel。可在全局或 Channel 层配置亲和。优先 Channel 仍须满足资格和健康规则。Responses 的 `previous_response_id` 历史由 Monoize 在内部解析，不要求上游保存状态。

## 时间指标

[请求日志](/zh/docs/request-logs)中的每一行记录总耗时、首字节时间和可见输出的每秒 Token 数。修改权重之前，用这些数值比较各个 Channel。

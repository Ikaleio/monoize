## 日誌列表

開啟側邊欄中的**日誌**。Monoize 為每個通過 API 金鑰認證的轉發請求記錄一行。每行顯示：

- 邏輯模型、服務的 Provider 和 Channel，以及 API 金鑰名稱；
- Token 數量：輸入、輸出、快取讀取、快取建立和推理 Token；
- 以美元計的費用；
- 狀態：`pending`、`success`、`error` 或 `client_gone`；
- 時間指標：總耗時、首位元組時間，以及串流請求的每秒 Token 數。

列表透過伺服器推送事件（SSE）即時更新。新行自動出現，無需手動重新整理。

## 失敗的嘗試

當一個請求經過多次上游嘗試時，該行會按順序列出每一跳失敗記錄。每一跳顯示 Provider、Channel、上游狀態碼和錯誤文字。透過這個列表可以看到哪個 Channel 失敗了，以及請求為什麼繼續前進。

## 請求擷取

擷取功能把每次上游嘗試的完整封包儲存到磁碟。擷取預設關閉。兩個開關控制它：

1. **系統開關。** `super_admin` 在**設定**中啟用請求擷取。系統開關關閉時，任何金鑰都不會寫入擷取檔案。
2. **金鑰級模式。** 每個 API 金鑰設定 `request_capture_mode`：
   - `off`：從不擷取。
   - `capture-all`：擷取每個到達上游的請求。
   - `capture-only-abnormal`：只擷取失敗或異常的請求。

### 保留與輪替

每個 API 金鑰設定 `request_capture_retention`：`5m`、`1h`、`24h` 或 `7d`。預設為 `24h`。擷取在該期限後過期。清理任務在程序啟動時執行一次，之後每小時執行一次，刪除已過期的擷取。

`super_admin` 可以在**設定**中配置 `monoize_request_capture_max_total_bytes`。面板以 MiB 顯示該值。當全部擷取的總大小超過上限時，Monoize 從最舊的擷取開始刪除，直到總大小不超過上限。設為 `0` 表示不限制。

Monoize 在背景任務中用 zstd 壓縮新的擷取檔案，同時仍能讀取舊版本寫入的未壓縮檔案。

## 擷取檢視器

有擷取記錄的行會顯示擷取標記。點擊標記開啟檢視器。檢視器為每次嘗試顯示：

- **下游請求**：用戶端發來的原始請求主體；
- **上游請求**：編碼後實際發往上游的請求；
- **URP**：經過所有變換後的請求；
- **回應**：非串流的最終結果。對於串流請求，Monoize 顯示重建後的完整回應；
- **輸出串流**：串流請求的原始 SSE 幀，帶語法突顯。僅當該次嘗試記錄了串流幀時才顯示此分頁；
- 實際執行的變換鏈，包括範圍和順序。

`user` 角色只能檢視自己的擷取，且只能看到 API 金鑰範圍的變換條目。管理員可以檢視 `user` 角色帳戶的擷取。

## 疑難排解

| 現象 | 原因 | 處理 |
| --- | --- | --- |
| 新行沒有擷取標記 | 擷取持久化晚於即時行到達 | 等待列表自動重新整理，或重新整理一次頁面 |
| `capture_not_found` | 擷取已過期、已被輪替刪除，或你的角色無權檢視 | 提高該金鑰的擷取保留期，或聯絡擷取所有者 |
| 某個金鑰的行缺失 | 該金鑰屬於其他使用者 | 以金鑰所有者或管理員身分登入 |

## ルート選択

Monoize は各リクエストのルートを次の順序で解決します。

1. **モデルリダイレクト。** API キーのルールが先に実行され、次にグローバルルールが実行されます。最初に一致したルールがモデル名を書き換えます。
2. **Provider 選択。** Monoize は次の条件を満たす有効な Provider を収集します: 有効かつ重みが 0 より大きい Channel が対象モデルを 1 つ以上提供していること、およびグループがキーのグループと交差していること。グループの順序が優先順位を決めます。同一グループ内では Provider の優先度が適用されます。
3. **Channel 選択。** 選択された Provider 内で、Monoize は候補 Channel を重み付きランダムで並べます。Channel $i$ が最初に試行される確率は次のとおりです。

```math
P(i) = \frac{w_i}{\sum_{j=1}^{n} w_j}
```

したがって、重み `2` の Channel は重み `1` の Channel の 2 倍のトラフィックを受けます。

## リトライとフォールバック

Monoize はルートを入れ子順で試行します。まず 1 つの Provider 内の Channel を試し、次の Provider へ進みます。

- 各 Channel は `channel_max_retries + 1` 回の試行を得ます。デフォルトは 1 回で、Channel 内リトライはありません。
- `channel_retry_interval_ms` は Channel 内リトライの間に待機を挿入します。デフォルトは `0` です。
- `max_retries` は Provider 全体の合計試行回数を制限します。
- 1 つの Provider を使い切ると、Monoize は次の適格な Provider へ進みます。
- すべての Provider を使い切ると、クライアントは HTTP `502`（エラーコード `upstream_error`）を受け取ります。

### 同一 Channel をリトライするエラー

| エラー | 同一 Channel リトライ | 次のルートへ前進 |
| --- | --- | --- |
| HTTP `408`、`429`、`5xx` | あり | あり（Channel の試行回数を使い切った後） |
| タイムアウト、接続拒否・リセット | あり | あり（Channel の試行回数を使い切った後） |
| その他の上流エラー（例: `400`、`401`、`404`） | なし | あり（直ちに前進） |
| Monoize 側のエラー（認証、残高、検証、課金） | なし | なし（ルーティング終了） |

## ストリーミング保証

最初のレスポンスバイトがクライアントに届いた時点でフォールバックは終了します。それ以前は、Monoize は Channel と Provider を自由に切り替えられます。それ以降、Monoize は切り替えを行いません。したがって、可視ストリームは常に 1 回の生成に由来します。

## サーキットブレーカー

各 Provider には `circuit_breaker_enabled` があります。有効な場合:

- Channel は `window_seconds`（デフォルト `30`）以内に `failure_count_threshold`（デフォルト `3`）回のリトライ可能な失敗を起こすと不健全になります。
- 不健全な Channel は `cooldown_seconds`（デフォルト `60`）の間スキップされます。HTTP `429` による失敗は `rate_limit_cooldown_seconds`（デフォルト `15`）を使います。
- `per_model_circuit_break` を有効にすると、健全性は Channel 単位ではなく `(Channel, モデル)` の組み合わせで追跡されます。
- アクティブプローブを有効にすると、Monoize はクールダウンを終えた Channel をバックグラウンドで検査し、成功しきい値に達すると復帰させます。

Provider の `circuit_breaker_enabled` を `false` にすると、その Provider の健全性状態は無視されます。パッシブ遮断とアクティブプローブも停止します。

## セッションアフィニティ

Monoize は会話をそれを処理した Channel に結び付けられます。サーバー側状態を持つ後続リクエスト（例: Responses の `previous_response_id`）は同じ上流に到達します。アフィニティはグローバルおよび Channel 単位で設定できます。アフィニティで優先された Channel も、適格性と健全性のルールに従います。

## タイミング指標

[リクエストログ](/ja/docs/request-logs)の各行には、合計時間、最初のバイトまでの時間、可視出力の秒間トークン数が記録されます。重みを変更する前に、これらの値で Channel を比較してください。

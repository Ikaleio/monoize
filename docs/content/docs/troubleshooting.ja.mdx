## まずログを確認する

設定を変更する前に、ダッシュボードの**リクエストログ**を開きます。失敗した各リクエストの行には、エラーコード、HTTP ステータス、失敗した上流試行がすべて表示されます。[リクエストキャプチャ](/ja/docs/request-logs)を有効にすると、上流の正確なペイロードを検査できます。

## 認証エラー

### `401 unauthorized`

1. キーが `sk-` で始まり、完全であることを確認します。
2. **API キー**で、キーが有効で期限切れでないことを確認します。
3. キーの所有ユーザーアカウントが有効であることを確認します。
4. ヘッダー形式を確認します: `Authorization: Bearer sk-...` または `x-api-key: sk-...`。

### `403 model_not_allowed`

キーのモデル制限が有効で、要求モデルがどのエントリとも一致していません。正確な論理モデル名をキーのモデルリストに追加するか、モデル制限を無効にします。

### `403 ip_not_allowed`

クライアント IP がキーの IP ホワイトリストにありません。アドレスまたは CIDR 範囲を追加するか、ホワイトリストを空にします。Monoize がリバースプロキシの背後にある場合は、プロキシが実際のクライアント IP を転送していることを確認します。

## ルーティングエラー

### `502 upstream_error`

モデルを提供するルートがない、最後の試行が上流コードなしで失敗した、または上流が Channel の認証情報を拒否しました。次の順序で確認します。

1. **Channel の認証情報が拒否された。** ボディの `upstream_status` が `401`、`403`、`407` のいずれかです。Channel のキーまたは権限を修正します。クライアントのキーは有効です。
2. **トランスポート障害。** メッセージが `failed to request upstream` です。Channel の base URL とプロキシを確認します。
3. **ルートが存在しない。** 有効な Provider が、モデルをマッピングした有効かつ重み 0 超の Channel を 1 つ以上持つことを確認します。
4. **グループが交差しない。** キーのグループは Provider と少なくとも 1 つのグループを共有する必要があります。[API キー](/ja/docs/dashboard/api-keys)を参照してください。
5. **他のルーティング条件を満たす Channel がすべて異常。** サーキットブレーカーが有効な場合、Monoize は異常な Channel にトラフィックを転送しません。プローブの連続成功回数がしきい値に達するか、ダッシュボードのテストが成功するか、復帰までの待機時間が過ぎると、転送を再開できます。ログで失敗した試行を確認し、上流のエラーを特定してください。
6. **倍率上限。** `max_multiplier` を設定したキーは、上限を超える価格のモデルエントリをスキップします。

### その他の上流ステータスとコード

クライアントは最後の上流のステータスとコード（`429 rate_limit_exceeded` など）を受け取ります。`stream: true` でも同じです。各ホップはログ行の失敗試行で確認します。`2xx` を受け取った後に失敗した試行があると、後続のエラーは HTTP `200` のストリーム内で届くことがあります。

### OpenAI Platform で `credit_balance_exhausted` または `insufficient_quota` が返る

Channel の API キーを所有する OpenAI Platform アカウントのクレジットが切れています。OpenAI は HTTP `429` を返すか、HTTP `200` のレスポンスヘッダーを送った後にストリーム内でエラーを報告します。Monoize はどちらも恒久的な障害として扱います。サーキットブレーカーが有効な場合、Channel または影響を受けたモデルは直ちに異常になります。

OpenAI Platform でクレジットを追加してください。アクティブプローブの成功を待つか、影響を受けたモデルの [Channel テスト](/ja/docs/dashboard/providers-and-channels) を実行してください。テストが成功すると直ちに正常に戻ります。レプリカノードの Channel は、復帰までの待機時間が過ぎても正常に戻ります。

### `400 unsupported_tool`

リクエストが `openrouter:*` ツール、または Chat エンコードのない他のツールタイプを、それを表現できない Chat ダイアレクトへ送っています。ツールを削除するか、モデルを `openrouter` または `generic` ダイアレクトの Channel へルーティングします。[API エンドポイント](/ja/docs/endpoints)を参照してください。

### Chat のツール結果で `400 unsupported_media` が返る

- `Chat tool results support text only; image content cannot be discarded.`
- `Chat tool results support text only; file content cannot be discarded.`

選択された Chat ダイアレクトでは、ツール結果の画像やファイルを送れません。Monoize はその試行でリクエストを上流に送らず、試行回数の上限内で次の条件を満たす Channel または Provider を試します。対応するルートがない場合は、その内容を送れる Channel にモデルをルーティングしてください。たとえば、`openrouter` ダイアレクトを使う Chat Channel や、対応する Responses、Messages、Gemini の Channel を選んでください。対応可否はメディアの形式と取得元によって異なります。

### 組み込みツールが効かない

ファミリーをまたぐルートでは、マッピングされた組み込みツールだけが残ります。Monoize は他の組み込みツールをエラーなしで削除し、削除されたツールの強制選択は `auto` になります。[API エンドポイント](/ja/docs/endpoints)を参照してください。

### エラーメッセージに `***` が表示される

Monoize はクライアント向けエラーテキストのホスト名、URL、IP アドレス、API キーをマスクします。管理者は[リクエストログ](/ja/docs/request-logs)で全文を確認できます。

### リクエストが常に 1 つの Channel に集中する

重み付き選択はリクエストごとにランダムです。サンプルが少ないと偏って見えることがあります。セッションアフィニティが意図的に会話を 1 つの Channel に固定していないかも確認します。

## 課金エラー

### `402 insufficient_balance`

ユーザー残高、またはキーのサブアカウント残高がゼロ以下です。**ユーザー管理**で残高を追加するか、キーのサブアカウントオプションを無効にします。

### 課金額がおかしい

課金額 = 基本価格 × グループの `billing_ratio` × Channel モデルエントリの `multiplier` です。**モデル料金**ページでそのモデルに有効な価格レコードがあることを確認します。**グループ**ページでグループの課金倍率を確認します。Channel モデルエントリの倍率を確認します。倍率が `0` の場合、その Channel は無料です。

## ストリーミングの問題

### ストリームが途中で止まる

最初のプロトコルイベント以降、Monoize は上流を切り替えません。途中で切れたストリームは上流の障害を反映しています。HTTP ステータスはすでに `200` のため、クライアントはストリーム内で `error` イベントを受け取ります。ログ行を読み、キャプチャを有効にして上流の生フレームを確認します。

### クライアントが `[DONE]` を待ち続ける

`data: [DONE]` を送るのは Chat Completions ストリームだけです。Responses と Messages のストリームは終端イベントの後に終わります。クライアントが終端イベントで停止するように更新してください。

### Chat ストリームに使用量チャンクがない

リクエストで `stream_options.include_usage` を `true` にします。課金はこのオプションに依存しません。

### Responses WebSocket が閉じる、またはイベントを拒否する

- `websocket_connection_limit_reached` は、接続がターン、バイト、または接続時間の制限に達したことを示します。新しい接続を開いてください。接続時間の既定の制限は 60 分です。
- `previous_response_not_found` は、接続にそのキャッシュレスポンスがないことを示します。履歴全体を再送してください。
- `response.steer.failed` のコードが `steering_not_supported` の場合、そのターンまたは Channel はステアリングできません。レスポンスの完了を待ち、新しいターンで入力を送ってください。

すべてのコードは [Responses WebSocket](/ja/docs/endpoints) を参照してください。

### クライアントが長い SSE フレームを拒否する

一部のクライアントは SSE フレーム長を制限します。処理する Provider に `stream_split_sse_frames` 変換を追加します。[ストリーム: 長大 SSE フレームの分割](/ja/docs/transforms/stream_split_sse_frames)を参照してください。

### 上流がストリーミングを必須とする

`stream_force` 変換を追加して、上流へ `stream: true` を強制します。クライアントが非ストリーミングを要求した場合でも、Monoize はクライアントに非ストリーミングのレスポンスを返します。

## プロトコル変換に関する質問

### 変換後に推論内容が消える

一部の上流は非標準フィールドで推論内容を返します。推論系の変換ルールで復元または整形します。[変換ルール](/ja/docs/transforms)から始めてください。

### プロバイダー固有フィールドが上流に届かない

プロトコルファミリーをまたぐ変換は、安全な対応先のないプロバイダー固有のネストフィールドを除去します。`field_set` 変換で特定の Provider にフィールドを再設定します。

### レスポンスにプロバイダー固有フィールドがない

ファミリーをまたぐレスポンスでは、`metadata`、`container`、`stop_details` などのプロバイダー固有フィールドが失われます。このルールに設定はありません。これらのフィールドを残すには、同じプロトコルファミリーの Channel へルーティングします。

### クライアントがツール呼び出しの `4338.0` のような数値を拒否する

一部の上流は、ツール呼び出し引数の整数を JSON 浮動小数点で返します。Codex の `write_stdin` は `session_id` を整数として解析し、`4338.0` を拒否します。Monoize はクライアントへ返す前に、ツール呼び出し引数内の整数値浮動小数点を JSON 整数へ書き換えます。この書き換えに変換ルールは不要です。

## ダッシュボードへのアクセス

### 管理者パスワードを紛失した

別の `super_admin` が**ユーザー管理**でパスワードをリセットできます。他に `super_admin` がいない場合は、データベースで直接リセットします。

### 最初のアカウントが管理者にならない

最初に登録したアカウントが `super_admin` になります。このルールは一度だけ適用されます。以降のアカウントのデフォルトは `user` です。

## ログ一覧

サイドバーの**ログ**を開きます。Monoize は API キーで認証されたすべての転送リクエストを 1 行ずつ記録します。各行には次の情報が表示されます。

- 論理モデル、処理した Provider と Channel、API キー名
- トークン数: 入力、出力、キャッシュ読み取り、キャッシュ作成、推論トークン
- 米ドル建ての課金額
- ステータス: `pending`、`success`、`error`、`client_gone`
- タイミング: 合計時間、最初のバイトまでの時間、ストリームの秒間トークン数

一覧ではリアルタイム更新が既定で有効です。**リアルタイム更新**を無効にすると、イベントストリームとフォールバックポーリングが停止します。**更新**を使用して一覧を手動更新します。

## 失敗した試行

リクエストが複数回の上流試行を要した場合、その行は失敗した各ホップを順番に一覧表示します。各ホップには Provider、Channel、上流のステータスコード、エラーテキストが表示されます。この一覧で、どの Channel が失敗し、なぜリクエストが次へ進んだかを確認できます。

## リクエストキャプチャ

キャプチャは各上流試行の正確なペイロードをディスクに保存します。キャプチャはデフォルトで無効です。2 つのスイッチで制御します。

1. **システムスイッチ。** `super_admin` が**設定**でリクエストキャプチャを有効にします。このスイッチが無効の間は、どのキーでもキャプチャは書き込まれません。
2. **キー単位のモード。** 各 API キーが `request_capture_mode` を設定します。
   - `off`: キャプチャしない。
   - `capture-all`: 上流に到達したすべてのリクエストをキャプチャする。
   - `capture-only-abnormal`: 失敗または異常なリクエストのみキャプチャする。

キャプチャは次のエンドポイントに適用されます: `POST /v1/responses`、`POST /v1/chat/completions`、`POST /v1/messages`、`POST /v1/images/generations`、`POST /v1/images/edits`。

### Image API とマルチモーダルペイロード

Image API の各サブリクエストは 1 つのキャプチャを書き込みます。`n` が 1 より大きい場合、キャプチャのリクエスト ID に接尾辞 `:img:{i}` が付きます。`i` は 0 始まりのサブリクエスト番号です。

Monoize は `multipart/form-data` ボディを構造化 JSON オブジェクトとして保存します。オブジェクトは各パートを送信順に列挙します。テキストパートはフィールド名とテキストを記録します。ファイルパートはフィールド名、ファイル名、コンテンツタイプ、バイト長、base64 データを記録します。このルールは受信した `POST /v1/images/edits` ボディと、`openai_image` 上流へ送信する multipart フォームの両方に適用されます。

キャプチャは画像などのマルチモーダルコンテンツを元のボディのまま保持します。Monoize はマスキングも再エンコードも行いません。

### 保持とローテーション

各 API キーは `request_capture_retention` を設定します。値は `5m`、`1h`、`24h`、`7d` のいずれかです。デフォルトは `24h` です。キャプチャはこの期間の経過後に期限切れになります。クリーンアップタスクはプロセス起動時に 1 回、その後 1 時間ごとに実行され、期限切れのキャプチャを削除します。

`super_admin` は**設定**で `monoize_request_capture_max_total_bytes` を設定できます。ダッシュボードは値を MiB で表示します。全キャプチャの合計サイズが上限を超えると、Monoize は最も古いキャプチャから順に削除し、合計を上限以下に戻します。`0` を設定すると上限は無効になります。

Monoize は新しいキャプチャファイルをバックグラウンドタスクで zstd 圧縮します。旧バージョンが書き込んだ非圧縮ファイルも引き続き読み取れます。

## キャプチャビューア

キャプチャが保存された行にはキャプチャインジケーターが表示されます。クリックするとビューアが開きます。ビューアは試行ごとに次を表示します。

- **下流リクエスト**: クライアントから受信した元のリクエストボディ
- **上流リクエスト**: 上流に送信された正確なエンコード済みリクエスト
- **URP**: すべての変換適用後のリクエスト
- **レスポンス**: 非ストリーミングの最終結果。ストリーミング試行では、Monoize は再構築した完全なレスポンスを表示します
- **出力ストリーム**: ストリーミング試行の生 SSE フレーム（シンタックスハイライト付き）。このタブは試行がストリームフレームを記録した場合のみ表示されます
- 実行された変換チェーン（スコープと順序付き）

文字列が画像の data URL または base64 画像データを含む場合、ビューアはその下にインラインプレビューを表示します。デコードできない画像データはプレビューを折りたたみ、テキストのみ残します。

`user` ロールは自分のキャプチャのみ閲覧でき、API キースコープの変換エントリのみ表示されます。管理者は `user` ロールのアカウントが所有するキャプチャを閲覧できます。

## トラブルシューティング

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| 新しい行にキャプチャインジケーターがない | キャプチャの永続化がライブ行の到着より遅い | 一覧の自動更新を待つか、一度再読み込みする |
| `capture_not_found` | キャプチャの期限切れ、ローテーションによる削除、またはロールに閲覧権限がない | キーのキャプチャ保持期間を延ばすか、所有者に確認する |
| 特定キーの行が表示されない | そのキーは別のユーザーの所有 | キー所有者または管理者としてサインインする |

## 先看日誌

修改設定之前，先開啟儀表板中的**日誌**。每個失敗請求的行都顯示錯誤碼、HTTP 狀態和每次失敗的上游嘗試。開啟[請求擷取](/zh-TW/docs/request-logs)可以檢查上游的完整封包。

## 認證錯誤

### `401 unauthorized`

1. 確認金鑰以 `sk-` 開頭且完整。
2. 在**令牌管理**中確認金鑰已啟用且未過期。
3. 確認金鑰所屬的使用者帳戶已啟用。
4. 確認請求標頭格式：`Authorization: Bearer sk-...` 或 `x-api-key: sk-...`。

### `403 model_not_allowed`

金鑰開啟了模型限制，且請求的模型不等於任何條目。把精確的邏輯模型名加入金鑰的模型列表，或關閉模型限制。

### `403 ip_not_allowed`

用戶端 IP 不在金鑰的 IP 白名單中。新增該位址或 CIDR 網段，或清空白名單。Monoize 位於反向代理之後時，確認代理轉發了真實的用戶端 IP。

## 路由錯誤

### `502 upstream_error`

所有符合條件的路由都失敗，或沒有路由服務該模型。按以下順序檢查：

1. **路由不存在。** 確認至少有一個已啟用的 Provider 擁有一個已啟用、權重大於零、且映射了該模型的 Channel。
2. **群組無交集。** 金鑰的群組必須與 Provider 至少共享一個群組。參見 [API 金鑰](/zh-TW/docs/dashboard/api-keys)。
3. **所有 Channel 不健康。** 斷路器在冷卻期內跳過不健康的 Channel。檢視日誌行中的失敗嘗試，找到根本的上游錯誤。
4. **倍率上限。** 設定了 `max_multiplier` 的金鑰會跳過價格高於上限的模型條目。

### 請求總是命中同一個 Channel

權重選擇對每個請求隨機。小樣本可能看起來不均衡。同時檢查工作階段親和是否有意把會話綁定到了一個 Channel。

## 計費錯誤

### `402 insufficient_balance`

使用者餘額或金鑰的子帳戶餘額為零或負數。在**使用者**中儲值，或關閉金鑰的子帳戶選項。

### 費用看起來不對

費用 = 模型基礎價格 × Channel 模型條目的 `multiplier`。在**模型**頁面確認該模型有中繼資料價格，並檢查 Channel 模型條目上的倍率。

## 串流問題

### 串流在回應中途停止

第一個回應位元組之後，Monoize 絕不切換上游。中途斷掉的串流反映的是上游故障。檢視日誌行，並開啟擷取檢視上游原始幀。

### 用戶端拒絕超長 SSE 幀

某些用戶端限制 SSE 幀長度。在服務的 Provider 上新增 `stream_split_sse_frames` 變換。參見[串流：拆分超長 SSE 幀](/zh-TW/docs/transforms/stream_split_sse_frames)。

### 上游要求串流請求

新增 `stream_force` 變換，強制向上游發送 `stream: true`。用戶端請求非串流時，Monoize 仍然向用戶端返回非串流回應。

## 協議轉換問題

### 轉換後推理內容消失

某些上游用非標準欄位返回推理內容。使用推理類變換還原或改寫。從[變換](/zh-TW/docs/transforms)開始。

### 提供商私有欄位沒有到達上游

跨協議族轉換會移除沒有安全目標表示的提供商私有巢狀欄位。使用 `field_set` 變換為某個 Provider 重新寫入欄位。

## 儀表板存取

### 管理員密碼遺失

另一個 `super_admin` 可以在**使用者**中重設密碼。沒有其他 `super_admin` 時，直接在資料庫中重設。

### 第一個帳戶不是管理員

第一個註冊的帳戶成為 `super_admin`。此規則只生效一次。之後的帳戶預設為 `user`。

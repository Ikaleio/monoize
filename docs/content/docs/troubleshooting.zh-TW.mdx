## 先看日誌

修改設定之前，先開啟儀表板中的**請求日誌**。每個失敗請求的行都顯示錯誤碼、HTTP 狀態和每次失敗的上游嘗試。開啟[請求擷取](/zh-TW/docs/request-logs)可以檢查上游的完整封包。

## 認證錯誤

### `401 unauthorized`

1. 確認金鑰以 `sk-` 開頭且完整。
2. 在 **API 金鑰**中確認金鑰已啟用且未過期。
3. 確認金鑰所屬的使用者帳戶已啟用。
4. 確認請求標頭格式：`Authorization: Bearer sk-...` 或 `x-api-key: sk-...`。

### `403 model_not_allowed`

金鑰開啟了模型限制，且請求的模型不等於任何條目。把精確的邏輯模型名加入金鑰的模型列表，或關閉模型限制。

### `403 ip_not_allowed`

用戶端 IP 不在金鑰的 IP 白名單中。新增該位址或 CIDR 網段，或清空白名單。Monoize 位於反向代理之後時，確認代理轉發了真實的用戶端 IP。

## 路由錯誤

### `502 upstream_error`

沒有路由服務該模型，最後一次嘗試失敗且沒有上游錯誤碼，或上游拒絕了 Channel 憑證。按以下順序檢查：

1. **Channel 憑證被拒絕。** 回應主體中的 `upstream_status` 為 `401`、`403` 或 `407`。請修復 Channel 金鑰或權限。用戶端金鑰有效。
2. **傳輸失敗。** 訊息為 `failed to request upstream`。檢查 Channel base URL 和代理。
3. **路由不存在。** 確認至少有一個已啟用的 Provider 擁有一個已啟用、權重大於零、且映射了該模型的 Channel。
4. **群組無交集。** 金鑰的群組必須與 Provider 至少共享一個群組。參見 [API 金鑰](/zh-TW/docs/dashboard/api-keys)。
5. **所有 Channel 不健康。** 斷路器在冷卻期內跳過不健康的 Channel。檢視日誌行中的失敗嘗試，找到根本的上游錯誤。
6. **倍率上限。** 設定了 `max_multiplier` 的金鑰會跳過價格高於上限的模型條目。

### 其他上游狀態碼和錯誤碼

用戶端收到最後一次上游的狀態碼和錯誤碼，例如 `429 rate_limit_exceeded`。`stream: true` 時同樣如此。檢視日誌行中的失敗嘗試可了解每一跳。如果某次嘗試收到 `2xx` 後才失敗，之後的錯誤會以 HTTP `200` 在串流中傳回。

### `400 unsupported_tool`

請求把 `openrouter:*` 工具或其他沒有 Chat 編碼的工具類型傳送給無法表示它的 Chat 方言。請移除該工具，或把模型路由到 `openrouter` 或 `generic` 方言的 Channel。參見 [API 端點](/zh-TW/docs/endpoints)。

### 內建工具沒有生效

跨協議族路由只保留已對應的內建工具。Monoize 捨棄其他內建工具且不報錯，強制選擇已捨棄工具時會變為 `auto`。參見 [API 端點](/zh-TW/docs/endpoints)。

### 錯誤訊息顯示 `***`

Monoize 會遮罩用戶端錯誤文字中的主機名稱、URL、IP 位址和 API 金鑰。管理員可在[請求日誌](/zh-TW/docs/request-logs)中檢視完整文字。

### 請求總是命中同一個 Channel

權重選擇對每個請求隨機。小樣本可能看起來不均衡。同時檢查工作階段親和是否有意把會話綁定到了一個 Channel。

## 計費錯誤

### `402 insufficient_balance`

使用者餘額或金鑰的子帳戶餘額為零或負數。在**使用者管理**中儲值，或關閉金鑰的子帳戶選項。

### 費用看起來不對

費用 = 基礎價格 × 群組 `billing_ratio` × Channel 模型條目的 `multiplier`。在**模型定價**頁面確認該模型有已啟用的價格記錄。在**群組**頁面檢查群組的計費倍率。檢查 Channel 模型條目上的倍率。倍率為 `0` 時該 Channel 免費。

## 串流問題

### 串流在回應中途停止

第一個協定事件之後，Monoize 絕不切換上游。中途斷掉的串流反映的是上游故障。HTTP 狀態碼已經是 `200`，因此用戶端在串流中收到 `error` 事件。檢視日誌行，並開啟擷取檢視上游原始幀。

### 用戶端在等待 `[DONE]`

只有 Chat Completions 串流傳送 `data: [DONE]`。Responses 和 Messages 串流在終態事件後結束。請更新用戶端，使其在終態事件處停止。

### Chat 串流沒有用量區塊

在請求中將 `stream_options.include_usage` 設為 `true`。計費不依賴此選項。

### Responses WebSocket 關閉或拒絕事件

- `websocket_connection_limit_reached` 表示連線達到了輪次、位元組或時長限制。請開啟新連線。預設時長限制為 60 分鐘。
- `previous_response_not_found` 表示連線中沒有該快取回應。請重新傳送完整歷史。
- `response.steer.failed` 的錯誤碼為 `steering_not_supported` 時，表示該輪次或 Channel 不支援 steer。請等回應結束，再在新輪次中傳送輸入。

所有錯誤碼參見 [Responses WebSocket](/zh-TW/docs/endpoints)。

### 用戶端拒絕超長 SSE 幀

某些用戶端限制 SSE 幀長度。在服務的 Provider 上新增 `stream_split_sse_frames` 變換。參見[串流：拆分超長 SSE 幀](/zh-TW/docs/transforms/stream_split_sse_frames)。

### 上游要求串流請求

新增 `stream_force` 變換，強制向上游發送 `stream: true`。用戶端請求非串流時，Monoize 仍然向用戶端返回非串流回應。

## 協議轉換問題

### 轉換後推理內容消失

某些上游用非標準欄位返回推理內容。使用推理類變換還原或改寫。從[變換](/zh-TW/docs/transforms)開始。

### 提供商私有欄位沒有到達上游

跨協議族轉換會移除沒有安全目標表示的提供商私有巢狀欄位。使用 `field_set` 變換為某個 Provider 重新寫入欄位。

### 回應中缺少提供商私有欄位

跨協議族回應會遺失提供商私有欄位，例如 `metadata`、`container` 和 `stop_details`。此規則沒有開關。要保留這些欄位，請把模型路由到同協議族的 Channel。

### 用戶端拒絕工具呼叫中的 `4338.0` 這類數字

部分上游在工具呼叫參數裡把整數寫成 JSON 浮點數。Codex 的 `write_stdin` 把 `session_id` 解析為整數，並拒絕 `4338.0`。Monoize 在把回應發給用戶端之前，會把工具呼叫參數中的整數值浮點數改寫為 JSON 整數。此改寫不需要變換規則。

## 儀表板存取

### 管理員密碼遺失

另一個 `super_admin` 可以在**使用者管理**中重設密碼。沒有其他 `super_admin` 時，直接在資料庫中重設。

### 第一個帳戶不是管理員

第一個註冊的帳戶成為 `super_admin`。此規則只生效一次。之後的帳戶預設為 `user`。

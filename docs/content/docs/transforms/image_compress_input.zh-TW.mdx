## 行為

此變換重新編碼 user 訊息中的內嵌圖片和工具結果中的圖片。它也處理函式工具參數 JSON 中的圖片 data URL 和圖片區塊。可用 `max_edge_px` 縮放這些圖片。自訂工具的自由文字及其他 Base64 保持不變。

`skip_if_smaller` 開啟時（預設），壓縮沒有減小體積的圖片保留原始位元組。

對於 JPEG、PNG 和 WebP 位元組，此變換依實際格式識別媒體類型。即使 `skip_if_smaller` 保留原始位元組，它也會修正不相符的媒體類型。

如果圖片帶有 alpha 通道，且選定的輸出格式為 `jpg`，此變換會保留原始位元組、媒體類型和尺寸。即使所有像素均不透明，也適用此規則。此規則優先於 `max_edge_px` 和 `skip_if_smaller`，以保留透明資訊和圖像遮罩。請求不含遮罩時，支援 alpha 通道的格式仍依設定壓縮。

如果編輯請求包含遮罩，此變換會跳過請求中的所有圖片，包括工具圖片。它會在查詢快取前保留圖片與遮罩的位元組、尺寸和對齊關係。

## 參考資訊

| 屬性 | 值 |
| --- | --- |
| 類型 ID | `image_compress_input` |
| 階段 | `request` |
| 範圍 | Provider, API 金鑰 |

## 適用場景

- 用戶端發送大照片或截圖，上游請求觸達大小限制。
- 你希望限制圖像解析度以控制成本。

## 設定

| 選項 | 類型 | 必填 | 預設值 | 說明 |
| --- | --- | --- | --- | --- |
| `output_format` | string | 否 | `"original"` | `original`、`jpg`、`jpegxl_lossless`、`jpegxl`、`webp_lossless`、`webp` 或 `png`。 |
| `max_edge_px` | integer | 否 | — | 最大寬度或高度（像素）。省略則保留原始尺寸。 |
| `jpeg_quality` | integer | 否 | `80` | JPEG 輸出的品質，1-100。 |
| `jpegxl_quality` | integer | 否 | `90` | 有損 JPEG XL 輸出的品質，1-99。 |
| `jpegxl_effort` | integer | 否 | `7` | JPEG XL 編碼力度，1-10。數值越高壓縮越慢。 |
| `webp_quality` | integer | 否 | `80` | 有損 WebP 輸出的品質，1-100。 |
| `skip_if_smaller` | boolean | 否 | `true` | 壓縮沒有減小體積時保留原圖。 |

### 範例規則

```json
{
  "transform": "image_compress_input",
  "enabled": true,
  "phase": "request",
  "models": [
    "*"
  ],
  "config": {
    "output_format": "webp",
    "max_edge_px": 1568,
    "webp_quality": 80
  }
}
```

設定環境變數 `MONOIZE_IMAGE_TRANSFORM_MAX_*` 可以限制解碼開銷。參見[設定](/zh-TW/docs/configuration)。

---
title: "画像: リクエスト画像の圧縮"
description: 上流エンコード前に、user 画像とツール画像を再エンコードします。
---

## 動作

この変換は user メッセージ内の画像とツール結果内の画像を再エンコードします。関数ツール引数の JSON にある画像 data URL と画像ブロックも処理します。対象画像は `max_edge_px` でリサイズできます。カスタムツールの自由形式入力と画像以外の Base64 は変更しません。

`skip_if_smaller` が有効な場合（デフォルト）、圧縮でサイズが減らない画像は元のバイト列を維持します。

JPEG、PNG、WebP のバイト列では、実際の形式を判定します。`skip_if_smaller` が元のバイト列を維持する場合も、誤ったメディアタイプを修正します。

画像にアルファチャンネルがあり、選択した出力形式が `jpg` の場合、元のバイト列、メディアタイプ、寸法を維持します。すべてのピクセルが不透明でも、このルールを適用します。透明情報と画像マスクを保持するため、このルールは `max_edge_px` と `skip_if_smaller` より優先します。マスクがないリクエストでは、アルファチャンネルをサポートする形式を設定に従って圧縮します。

編集リクエストにマスクがある場合、ツール画像を含むすべてのリクエスト画像をスキップします。キャッシュ参照前に、画像とマスクのバイト列、寸法、位置関係を維持します。

## リファレンス

| 項目 | 値 |
| --- | --- |
| タイプ ID | `image_compress_input` |
| フェーズ | `request` |
| スコープ | Provider, API キー |

## 使いどころ

- クライアントが大きな写真やスクリーンショットを送信し、上流リクエストがサイズ制限に達する。
- コスト管理のために画像解像度を制限したい。

## 設定

| オプション | 型 | 必須 | デフォルト | 説明 |
| --- | --- | --- | --- | --- |
| `output_format` | string | いいえ | `"original"` | `original`、`jpg`、`jpegxl_lossless`、`jpegxl`、`webp_lossless`、`webp`、`png` のいずれか。 |
| `max_edge_px` | integer | いいえ | — | 最大の幅または高さ（ピクセル）。省略すると元の寸法を維持します。 |
| `jpeg_quality` | integer | いいえ | `80` | JPEG 出力の品質（1〜100）。 |
| `jpegxl_quality` | integer | いいえ | `90` | 非可逆 JPEG XL 出力の品質（1〜99）。 |
| `jpegxl_effort` | integer | いいえ | `7` | JPEG XL のエンコード労力（1〜10）。値が大きいほど圧縮が遅くなります。 |
| `webp_quality` | integer | いいえ | `80` | 非可逆 WebP 出力の品質（1〜100）。 |
| `skip_if_smaller` | boolean | いいえ | `true` | 圧縮でペイロードが小さくならない場合は元画像を維持します。 |

### ルール例

```json
{
  "transform": "image_compress_input",
  "enabled": true,
  "phase": "request",
  "models": [
    "*"
  ],
  "config": {
    "output_format": "webp",
    "max_edge_px": 1568,
    "webp_quality": 80
  }
}
```

環境変数 `MONOIZE_IMAGE_TRANSFORM_MAX_*` でデコード処理を制限できます。[設定](/ja/docs/configuration)を参照してください。

## 行為

當請求提交工具結果時，此變換在最後一個工具結果上插入 Anthropic ephemeral `cache_control` 快取斷點。每次提交工具結果時，快取斷點會隨對話前進。

沒有工具結果的請求原樣通過。

## 參考資訊

| 屬性 | 值 |
| --- | --- |
| 類型 ID | `cache_anthropic_tool_use` |
| 階段 | `request` |
| 範圍 | Provider, API 金鑰 |

## 適用場景

- 智慧代理用戶端在 Anthropic 相容上游上執行長工具迴圈。
- 你希望每輪迭代從快取中重讀會話前綴，而不是按全價支付輸入費用。

## 設定

| 選項 | 類型 | 必填 | 預設值 | 說明 |
| --- | --- | --- | --- | --- |
| `ttl` | string | 否 | `"5m"` | `5m` 或 `1h`。插入的快取斷點的有效期。`5m` 發送 `{"type": "ephemeral"}`，`1h` 額外加入 `"ttl": "1h"`。 |

1 小時快取寫入按基礎輸入價的 2 倍計費，5 分鐘快取寫入按 1.25 倍計費。

`1h` 斷點位於 `5m` 斷點之後時，Anthropic 會拒絕請求。所有 Anthropic `cache_*` 規則應使用相同的 `ttl`，或只在靠前的斷點上使用 `1h`。

Provider 規則先於 API 金鑰規則執行。後執行的規則會改寫 Monoize 已插入斷點的 TTL，因此 API 金鑰規則覆蓋 Provider 規則。用戶端自帶的 `cache_control` 始終保持不變。

### 範例規則

```json
{
  "transform": "cache_anthropic_tool_use",
  "enabled": true,
  "phase": "request",
  "models": [
    "claude-*"
  ],
  "config": {}
}
```

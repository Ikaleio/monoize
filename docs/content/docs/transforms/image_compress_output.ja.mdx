---
title: "画像: レスポンス画像の圧縮"
description: レスポンスとストリームの assistant 画像とツール画像を再エンコードします。
---

## 動作

この変換は assistant 画像とツール結果内の画像を再エンコードします。関数ツール引数の JSON にある画像 data URL と画像ブロックも処理します。設定項目は `image_compress_input` と同じです。

ストリーム内の不完全な関数引数フラグメントは変更しません。完成した最終引数には圧縮後の画像を使用します。カスタムツールの自由形式入力と画像以外の Base64 は変更しません。

画像にアルファチャンネルがあり、選択した出力形式が `jpg` の場合、元のバイト列、メディアタイプ、寸法を維持します。すべてのピクセルが不透明でも、このルールを適用します。このルールは `max_edge_px` と `skip_if_smaller` より優先し、通常のレスポンスとストリームの両方に適用します。アルファチャンネルをサポートする形式では、設定に従って圧縮します。

## リファレンス

| 項目 | 値 |
| --- | --- |
| タイプ ID | `image_compress_output` |
| フェーズ | `response` |
| スコープ | Provider, API キー |

## 使いどころ

- 画像生成レスポンスが大きく、クライアントが転送コストを負担している。
- 上流のフォーマットに関係なく、出力フォーマットを WebP などに統一したい。

## 設定

| オプション | 型 | 必須 | デフォルト | 説明 |
| --- | --- | --- | --- | --- |
| `output_format` | string | いいえ | `"original"` | `original`、`jpg`、`jpegxl_lossless`、`jpegxl`、`webp_lossless`、`webp`、`png` のいずれか。 |
| `max_edge_px` | integer | いいえ | — | 最大の幅または高さ（ピクセル）。省略すると元の寸法を維持します。 |
| `jpeg_quality` | integer | いいえ | `80` | JPEG 出力の品質（1〜100）。 |
| `jpegxl_quality` | integer | いいえ | `90` | 非可逆 JPEG XL 出力の品質（1〜99）。 |
| `jpegxl_effort` | integer | いいえ | `7` | JPEG XL のエンコード労力（1〜10）。値が大きいほど圧縮が遅くなります。 |
| `webp_quality` | integer | いいえ | `80` | 非可逆 WebP 出力の品質（1〜100）。 |
| `skip_if_smaller` | boolean | いいえ | `true` | 圧縮でペイロードが小さくならない場合は元画像を維持します。 |

### ルール例

```json
{
  "transform": "image_compress_output",
  "enabled": true,
  "phase": "response",
  "models": [
    "*image*"
  ],
  "config": {
    "output_format": "webp",
    "webp_quality": 80
  }
}
```

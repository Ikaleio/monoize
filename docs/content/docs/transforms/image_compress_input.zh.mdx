title: "图像：压缩请求图片"
description: 在上游编码之前，对 user 消息中的 base64 图片重新编码并可选缩放。
---

## 行为

此变换对 user 消息中的 base64 图片重新编码，并可选缩放到 `max_edge_px`。更小的报文上传更快，还可以降低图像 token 成本。

`skip_if_smaller` 开启时（默认），压缩没有减小体积的图片保留原始字节。

## 参考信息

| 属性 | 值 |
| --- | --- |
| 类型 ID | `image_compress_input` |
| 阶段 | `request` |
| 范围 | Provider, API 密钥 |

## 适用场景

- 客户端发送大照片或截图，上游请求触达大小限制。
- 你希望限制图像分辨率以控制成本。

## 配置

| 选项 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `output_format` | string | 否 | `"original"` | `original`、`jpg`、`jpegxl_lossless`、`jpegxl`、`webp_lossless`、`webp` 或 `png`。 |
| `max_edge_px` | integer | 否 | — | 最大宽度或高度（像素）。省略则保留原始尺寸。 |
| `jpeg_quality` | integer | 否 | `80` | JPEG 输出的质量，1-100。 |
| `jpegxl_quality` | integer | 否 | `90` | 有损 JPEG XL 输出的质量，1-99。 |
| `jpegxl_effort` | integer | 否 | `7` | JPEG XL 编码力度，1-10。数值越高压缩越慢。 |
| `webp_quality` | integer | 否 | `80` | 有损 WebP 输出的质量，1-100。 |
| `skip_if_smaller` | boolean | 否 | `true` | 压缩没有减小体积时保留原图。 |

### 示例规则

```json
{
  "transform": "image_compress_input",
  "enabled": true,
  "phase": "request",
  "models": [
    "*"
  ],
  "config": {
    "output_format": "webp",
    "max_edge_px": 1568,
    "webp_quality": 80
  }
}
```

设置环境变量 `MONOIZE_IMAGE_TRANSFORM_MAX_*` 可以限制解码开销。参见[配置](/zh/docs/configuration)。

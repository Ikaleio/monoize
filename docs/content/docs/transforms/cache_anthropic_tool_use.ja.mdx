## 動作

リクエストがツール結果を送信するとき、この変換は最後のツール結果にキャッシュブレークポイントを設定します。Messages 上流はこれを ephemeral `cache_control` として受け取ります。ツール結果を送信するたびにキャッシュ位置が前へ進みます。

ブレークポイントは他の上流タイプへのルーティングでも保持されます。[プロトコルをまたぐキャッシュブレークポイント](/ja/docs/endpoints)を参照してください。他の上流タイプには `prompt_cache_breakpoint` を送る場合と、マーカーを送らない場合があります。

ツール結果のないリクエストは変更されずに通過します。

## リファレンス

| 項目 | 値 |
| --- | --- |
| タイプ ID | `cache_anthropic_tool_use` |
| フェーズ | `request` |
| スコープ | Provider, API キー |

## 使いどころ

- エージェントクライアントが Anthropic 互換の上流で長いツールループを実行する。
- 各反復で会話プレフィックスを全額の入力価格ではなくキャッシュから再読するようにしたい。

## 設定

| オプション | 型 | 必須 | デフォルト | 説明 |
| --- | --- | --- | --- | --- |
| `ttl` | string | いいえ | `"5m"` | `5m` または `1h`。挿入するブレークポイントのキャッシュ有効期間です。`5m` は `{"type": "ephemeral"}` を送信し、`1h` は `"ttl": "1h"` を追加します。 |

1 時間キャッシュの書き込みは基本入力価格の 2 倍、5 分キャッシュの書き込みは 1.25 倍で課金されます。

`1h` ブレークポイントが `5m` ブレークポイントの後にあると、Anthropic はリクエストを拒否します。すべての Anthropic `cache_*` ルールで同じ `ttl` を使うか、`1h` は前方のブレークポイントだけに使ってください。

Provider ルールは API キールールより先に実行されます。後から実行されるルールは Monoize が挿入したブレークポイントの TTL を書き換えるため、API キールールが Provider ルールより優先されます。クライアントが送信した `cache_control` は変更されません。

### ルール例

```json
{
  "transform": "cache_anthropic_tool_use",
  "enabled": true,
  "phase": "request",
  "models": [
    "claude-*"
  ],
  "config": {}
}
```

---
title: "自動キャッシュ: Anthropic リクエスト"
description: Anthropic Messages リクエストでトップレベルの自動キャッシュを有効にします。
---

## 動作

この変換はリクエスト JSON のトップレベルに `cache_control` を追加します。会話が伸びると、上流はキャッシュ位置を最後の対象ブロックへ移します。既存の `cache_control` は変更しません。

## 参照情報

| 項目 | 値 |
| --- | --- |
| Type ID | `cache_anthropic_auto` |
| Phase | `request` |
| Scopes | Provider, API key |

## 使用する場面

Channel が Anthropic の自動キャッシュを受け付ける場合に使います。安定した system プレフィックスには `cache_anthropic_system` を維持します。中継サービスがトップレベルの項目を受け付けることを確認してください。

## 設定

| オプション | 型 | 必須 | デフォルト | 説明 |
| --- | --- | --- | --- | --- |
| `ttl` | string | いいえ | `"5m"` | `5m` または `1h`。挿入するブレークポイントのキャッシュ有効期間です。`5m` は `{"type": "ephemeral"}` を送信し、`1h` は `"ttl": "1h"` を追加します。 |

1 時間キャッシュの書き込みは基本入力価格の 2 倍、5 分キャッシュの書き込みは 1.25 倍で課金されます。

`1h` ブレークポイントが `5m` ブレークポイントの後にあると、Anthropic はリクエストを拒否します。すべての Anthropic `cache_*` ルールで同じ `ttl` を使うか、`1h` は前方のブレークポイントだけに使ってください。最後のブロックに TTL の異なる明示的な `cache_control` がある場合も、Anthropic はリクエストを拒否します。

Provider ルールは API キールールより先に実行されます。後から実行されるルールは Monoize が挿入したブレークポイントの TTL を書き換えるため、API キールールが Provider ルールより優先されます。クライアントが送信した `cache_control` は変更されません。

```json
{
  "transform": "cache_anthropic_auto",
  "enabled": true,
  "phase": "request",
  "models": ["claude-*"],
  "config": {}
}
```

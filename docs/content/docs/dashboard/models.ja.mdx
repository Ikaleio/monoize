## 論理モデル

クライアントは論理モデル名でリクエストします。Monoize はその名前を Provider と Channel に解決します。クライアントが見る名前は、上流ベンダーの名前と一致する必要はありません。

1 つの論理モデルは、複数の Provider にまたがる複数の Channel に対応付けられます。クライアントを変更せずに、フェイルオーバーと負荷分散を実現できます。

![モデルデータベース](/images/en/models.webp)

## リダイレクト

Channel のモデルエントリでは、`redirect` に実際の上流モデル名を設定できます。

例：クライアントは `my-fast-model` を呼び出します。Channel A はそれを `gpt-4o-mini` に、Channel B は `claude-3-5-haiku-20241022` にリダイレクトします。課金とログは常に論理名を表示します。

## モデルメタデータと価格

**モデルデータベース**ページはモデルメタデータを保存します：コンテキストウィンドウ、機能、トークン単価。Monoize は [Models.dev](https://models.dev) からメタデータと価格を取り込みます。

課金の計算：

1. メタデータテーブルのモデル基本価格を取得します。
2. Channel モデルエントリの `multiplier` を掛けます。

料金はナノドル単位で各ユーザーの台帳に積算されます。

## モデル一覧

`GET /v1/models` は、呼び出し元 API キーが利用できる論理モデルを返します。結果はキーのモデル制限とグループ所属を反映します。

## モデルグロブ

変換ルールと一部の制限は、モデルグロブパターンに対応します。

- `*` は空を含む任意の文字列にマッチします。
- `?` はちょうど 1 文字にマッチします。
- マッチングは大文字小文字を区別し、モデル名全体に固定されます。

例：`gpt-4*` は `gpt-4o` と `gpt-4o-mini` にマッチします。`o4-mini` にはマッチしません。

## 論理モデル

クライアントは論理モデル名でリクエストします。Monoize はその名前を Provider と Channel に解決します。クライアントが見る名前は、上流ベンダーの名前と一致する必要はありません。

1 つの論理モデルは、複数の Provider にまたがる複数の Channel に対応付けられます。クライアントを変更せずに、フェイルオーバーと負荷分散を実現できます。

## リダイレクト

Channel のモデルエントリでは、`redirect` に実際の上流モデル名を設定できます。

例：クライアントは `my-fast-model` を呼び出します。Channel A はそれを `gpt-4o-mini` に、Channel B は `claude-3-5-haiku-20241022` にリダイレクトします。課金とログは常に論理名を表示します。

## モデル価格を設定

**モデル**ページを開き、価格、ツール料金、上流同期、グループ倍率を管理します。

1. **モデル価格**で Token 単価、リクエスト単価、または段階価格を設定します。価格の単位は USD です。
2. **価格未設定モデル**で、有効な価格がないルーティング対象モデルを確認します。
3. **ツール価格**で、サーバー側ネイティブツールの料金を設定します。
4. **上流同期**で、models.dev、OpenRouter、または new-api の価格をプレビューして適用します。
5. **グループ価格**で、各グループの `billing_ratio` を設定します。

models.dev の同期を適用すると、Monoize は同じスナップショットから価格とメタデータを更新します。価格を手動で変更すると、そのフィールドがロックされます。後続の同期はロック済みフィールドを保持します。

Monoize は、リダイレクト後の上流モデルを先に解決します。リダイレクトがあり、上流モデルに価格がない場合だけ論理モデルにフォールバックします。

Monoize は基本料金に Channel モデルの `multiplier` と実際のルーティンググループの `billing_ratio` を掛けます。最終料金を nano-USD で記録します。

Monoize は既定で、価格未設定モデルと必要な Usage がない応答を拒否します。ゼロ料金での精算を許可する場合だけ、グローバル設定または Provider の上書きを有効にします。

## モデル一覧

`GET /v1/models` は、呼び出し元 API キーが利用できる論理モデルを返します。結果はキーのモデル制限とグループ所属を反映します。

## モデルグロブ

変換ルールと一部の制限は、モデルグロブパターンに対応します。

- `*` は空を含む任意の文字列にマッチします。
- `?` はちょうど 1 文字にマッチします。
- マッチングは大文字小文字を区別し、モデル名全体に固定されます。

例：`gpt-4*` は `gpt-4o` と `gpt-4o-mini` にマッチします。`o4-mini` にはマッチしません。

## 論理モデル

クライアントは論理モデル名でリクエストします。Monoize はその名前を Provider と Channel に解決します。クライアントが見る名前は、上流ベンダーの名前と一致する必要はありません。

1 つの論理モデルは、複数の Provider にまたがる複数の Channel に対応付けられます。クライアントを変更せずに、フェイルオーバーと負荷分散を実現できます。

## リダイレクト

Channel のモデルエントリでは、`redirect` に実際の上流モデル名を設定できます。

例：クライアントは `my-fast-model` を呼び出します。Channel A はそれを `gpt-4o-mini` に、Channel B は `claude-3-5-haiku-20241022` にリダイレクトします。課金とログは常に論理名を表示します。

## モデル価格

**モデル**ページは価格コンソールです。5 つのタブがあります。

- **モデル価格**：モデルごとに 1 件の価格レコード。各レコードは課金モードを設定します：`per_token`、`per_request`、`tiered_expr`。
- **未価格モデル**：対応付け済みで、有効な価格レコードがないモデル。
- **ツール価格**：サーバー側ツールクラスの価格。単位は `1k_calls`、`minute`、`session` です。
- **上流同期**：Models.dev、OpenRouter、または new-api インスタンスから価格を取り込みます。
- **グループ価格**：グループごとに 1 つの課金倍率。

Monoize は次の順序で料金を計算します。

1. モデルの価格レコードと記録された使用量から基本料金を計算します。
2. グループの `billing_ratio` を掛けます。
3. Channel モデルエントリの `multiplier` を掛けます。
4. ナノドルの整数値に切り捨てます。

Channel の `multiplier` が `0` の場合、その Channel のリクエストは無料です。

Monoize は、リダイレクト後の上流モデルを先に解決します。リダイレクトがあり、上流モデルに価格がない場合だけ論理モデルにフォールバックします。

Monoize は基本料金に Channel モデルの `multiplier` と実際のルーティンググループの `billing_ratio` を掛けます。最終料金を nano-USD で記録します。

Monoize は既定で、価格未設定モデルと必要な Usage がない応答を拒否します。ゼロ料金での精算を許可する場合だけ、グローバル設定または Provider の上書きを有効にします。

## 価格同期

1. **モデル → 上流同期**を開きます。
2. データソースを選択します：Models.dev、OpenRouter、または new-api インスタンス。
3. **プレビュー**をクリックします。テーブルは新規レコードと変更フィールドを表示します。
4. **適用**をクリックします。Monoize は変更を書き込み、監査レコードを記録します。

同期はロックされたフィールドを変更しません。同期は手動で作成したレコードを削除しません。

自動同期はデフォルトで有効です。Monoize はプロセスの起動時に 1 回同期し、その後は
24 時間ごとに同期します。各サイクルでは Models.dev を先に同期します。次に、Models.dev
が提供しないモデルを OpenRouter から追加します。以降の同期を停止するには、
**価格の自動同期**を無効にします。

## モデル一覧

`GET /v1/models` は、呼び出し元 API キーが利用できる論理モデルを返します。結果はキーのモデル制限とグループ所属を反映します。

## モデルグロブ

変換ルールと一部の制限は、モデルグロブパターンに対応します。

- `*` は空を含む任意の文字列にマッチします。
- `?` はちょうど 1 文字にマッチします。
- マッチングは大文字小文字を区別し、モデル名全体に固定されます。

例：`gpt-4*` は `gpt-4o` と `gpt-4o-mini` にマッチします。`o4-mini` にはマッチしません。

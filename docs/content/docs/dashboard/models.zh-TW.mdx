## 邏輯模型

客戶端請求的是邏輯模型名稱。Monoize 把這個名稱解析到你的 Provider 和 Channel。客戶端看到的名稱不需要與上游廠商的名稱一致。

一個邏輯模型可以對應到多個 Provider 下的多個 Channel。客戶端無需任何修改即可獲得容錯移轉和流量分配。

## 重新導向

Channel 的模型條目可以用 `redirect` 指定真實的上游模型名稱。

範例：客戶端呼叫 `my-fast-model`。Channel A 將其重新導向到 `gpt-4o-mini`，Channel B 將其重新導向到 `claude-3-5-haiku-20241022`。計費和日誌始終顯示邏輯名稱。

## 設定模型定價

開啟**模型**頁面，管理價格、工具費用、上游同步和群組倍率。

1. 在**模型定價**中設定 Token、單次請求或分級價格。價格單位是美元。
2. 在**未定價模型**中尋找沒有啟用價格的已路由模型。
3. 在**工具價格**中設定伺服器端原生工具費用。
4. 在**上游同步**中預覽或套用 models.dev、OpenRouter 或 new-api 的價格。
5. 在**群組定價**中設定每個群組的 `billing_ratio`。

套用 models.dev 同步時，Monoize 從同一份快照更新價格和中繼資料。手動修改價格會鎖定變更欄位。後續同步保留鎖定欄位。

Monoize 優先解析重新導向後的上游模型。僅在發生重新導向且上游模型沒有價格時，Monoize 才回退到邏輯模型。

Monoize 將基礎費用乘以 Channel 模型的 `multiplier` 和實際路由群組的 `billing_ratio`。最終費用以奈米美元記錄。

Monoize 預設拒絕未定價模型和缺少必要 Usage 的回應。僅在允許零費用結算時，啟用全域免費結算設定或 Provider 覆寫項目。

## 模型列表

`GET /v1/models` 回傳呼叫方 API 金鑰可用的邏輯模型。結果反映金鑰的模型限制和群組歸屬。

## 模型萬用字元

變換規則和部分限制支援模型萬用字元：

- `*` 匹配任意長度的字元序列，包括空序列。
- `?` 恰好匹配一個字元。
- 匹配區分大小寫，並錨定整個模型名稱。

範例：`gpt-4*` 匹配 `gpt-4o` 和 `gpt-4o-mini`，不匹配 `o4-mini`。

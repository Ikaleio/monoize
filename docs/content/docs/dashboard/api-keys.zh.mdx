## API 密钥的作用

客户端使用 API 密钥认证转发请求。每个密钥都以 `sk-` 开头。密钥可以放在以下任一请求头中：

```bash
Authorization: Bearer sk-...
# 或
x-api-key: sk-...
```

没有有效密钥的请求会收到 HTTP `401`。

![API 密钥管理](/images/zh/api-keys.webp)

## 创建密钥

1. 打开侧边栏中的**令牌管理**。
2. 点击创建按钮并输入名称。
3. 按需设置选项。所有选项都有安全的默认值。
4. 复制完整密钥。列表之后仍会显示完整密钥；Monoize 的密钥不是一次性展示。

## 密钥选项

| 选项 | 效果 | 默认值 |
| --- | --- | --- |
| 过期时间 | 到期后密钥停止工作。 | 永不过期 |
| 启用 | 禁用的密钥立即无法通过认证。 | 启用 |
| 模型限制 | 开启后，密钥只能调用列出的模型模式。 | 关闭 |
| IP 白名单 | 设置后，请求必须来自列出的 IPv4/IPv6 地址或 CIDR 网段。 | 空 |
| 分组 | 密钥只路由到分组有交集的 Provider。 | 继承用户分组 |
| 倍率上限 | 密钥跳过价格倍率超过该值的 Channel 模型条目。 | 无上限 |
| 子账户余额 | 开启后，密钥消耗自己的余额而不是用户余额。 | 关闭 |
| 请求捕获 | `off`、`capture-all` 或 `capture-only-abnormal`。参见[请求日志](/zh/docs/request-logs)。 | `off` |

## 模型限制

模型限制条目是精确的逻辑模型名。模型不等于任何条目的请求会收到 HTTP `403`，错误码为 `model_not_allowed`。

## 模型重定向

密钥可以持有一个有序的模型重定向规则列表。每条规则包含：

- `pattern`：正则表达式。Monoize 以 `^(pattern)$` 的形式对完整模型名做锚定匹配。
- `replace`：字面量目标模型名。

第一条匹配的规则在路由、计费和模型限制检查之前重写模型名。密钥规则先于全局规则执行。使用重定向可以在不修改客户端的情况下把流量切换到新模型。

## 分组

- **继承用户分组**（默认）：密钥跟随所属用户的分组。
- **显式分组**：选择一个或多个分组。顺序有意义；Monoize 优先选择排序靠前分组中的 Provider。参见[路由与可靠性](/zh/docs/routing)。

## 密钥级变换

密钥可以持有一个有序的变换链。密钥级变换受安全边界约束：只接受允许在 API 密钥范围使用的变换类型。参见[变换](/zh/docs/transforms)。

## API 金鑰的作用

用戶端使用 API 金鑰認證轉發請求。每個金鑰都以 `sk-` 開頭。金鑰可以放在以下任一請求標頭中：

```bash
Authorization: Bearer sk-...
# 或
x-api-key: sk-...
```

沒有有效金鑰的請求會收到 HTTP `401`。

![API 金鑰管理](/images/en/api-keys.webp)

## 建立金鑰

1. 開啟側邊欄中的**令牌管理**。
2. 點擊建立按鈕並輸入名稱。
3. 依需求設定選項。所有選項都有安全的預設值。
4. 複製完整金鑰。列表之後仍會顯示完整金鑰；Monoize 的金鑰不是一次性展示。

## 金鑰選項

| 選項 | 效果 | 預設值 |
| --- | --- | --- |
| 過期時間 | 到期後金鑰停止運作。 | 永不過期 |
| 啟用 | 停用的金鑰立即無法通過認證。 | 啟用 |
| 模型限制 | 開啟後，金鑰只能呼叫列出的模型模式。 | 關閉 |
| IP 白名單 | 設定後，請求必須來自列出的 IPv4/IPv6 位址或 CIDR 網段。 | 空 |
| 群組 | 金鑰只路由到群組有交集的 Provider。 | 繼承使用者群組 |
| 倍率上限 | 金鑰跳過價格倍率超過該值的 Channel 模型條目。 | 無上限 |
| 子帳戶餘額 | 開啟後，金鑰消耗自己的餘額而不是使用者餘額。 | 關閉 |
| 請求擷取 | `off`、`capture-all` 或 `capture-only-abnormal`。參見[請求日誌](/zh-TW/docs/request-logs)。 | `off` |

## 模型限制

模型限制條目是精確的邏輯模型名。模型不等於任何條目的請求會收到 HTTP `403`，錯誤碼為 `model_not_allowed`。

## 模型重新導向

金鑰可以持有一個有序的模型重新導向規則列表。每條規則包含：

- `pattern`：正規表示式。Monoize 以 `^(pattern)$` 的形式對完整模型名做錨定匹配。
- `replace`：字面量目標模型名。

第一條匹配的規則在路由、計費和模型限制檢查之前重寫模型名。金鑰規則先於全域規則執行。使用重新導向可以在不修改用戶端的情況下把流量切換到新模型。

## 群組

- **繼承使用者群組**（預設）：金鑰跟隨所屬使用者的群組。
- **顯式群組**：選擇一個或多個群組。順序有意義；Monoize 優先選擇排序靠前群組中的 Provider。參見[路由與可靠性](/zh-TW/docs/routing)。

## 金鑰級變換

金鑰可以持有一個有序的變換鏈。金鑰級變換受安全邊界約束：只接受允許在 API 金鑰範圍使用的變換類型。參見[變換](/zh-TW/docs/transforms)。

## 逻辑模型

客户端请求的是逻辑模型名。Monoize 把这个名字解析到你的 Provider 和 Channel。客户端看到的名字不需要与上游厂商的名字一致。

一个逻辑模型可以映射到多个 Provider 下的多个 Channel。客户端无需任何修改即可获得故障转移和流量分配。

## 重定向

Channel 的模型条目可以用 `redirect` 指定真实的上游模型名。

示例：客户端调用 `my-fast-model`。Channel A 将其重定向到 `gpt-4o-mini`，Channel B 将其重定向到 `claude-3-5-haiku-20241022`。计费和日志始终显示逻辑名。

## 配置模型定价

打开**模型**页面，管理价格、工具费用、上游同步和分组倍率。

1. 在**模型定价**中设置 Token、单次请求或阶梯价格。价格单位是美元。
2. 在**未定价模型**中查找没有启用价格的已路由模型。
3. 在**工具价格**中设置服务端原生工具费用。
4. 在**上游同步**中预览或应用 models.dev、OpenRouter 或 new-api 的价格。
5. 在**分组定价**中设置每个分组的 `billing_ratio`。

应用 models.dev 同步时，Monoize 从同一份快照更新价格和元数据。手动修改价格会锁定变更字段。后续同步保留锁定字段。

Monoize 优先解析重定向后的上游模型。仅当发生重定向且上游模型没有价格时，Monoize 才回退到逻辑模型。

Monoize 将基础费用乘以 Channel 模型的 `multiplier` 和实际路由分组的 `billing_ratio`。最终费用以纳美元记录。

Monoize 默认拒绝未定价模型和缺少必要 Usage 的响应。仅在允许零费用结算时，启用全局免费结算设置或 Provider 覆盖项。

## 模型列表

`GET /v1/models` 返回调用方 API 密钥可用的逻辑模型。结果反映密钥的模型限制和分组归属。

## 模型通配符

变换规则和部分限制支持模型通配符：

- `*` 匹配任意长度的字符序列，包括空序列。
- `?` 恰好匹配一个字符。
- 匹配区分大小写，并锚定整个模型名。

示例：`gpt-4*` 匹配 `gpt-4o` 和 `gpt-4o-mini`，不匹配 `o4-mini`。

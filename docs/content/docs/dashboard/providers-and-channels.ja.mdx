## 概念

- **Provider（プロバイダー）** はルーティンググループです。ルーティング順序、リトライ予算、ヘルスポリシー、順序付き変換チェーンを定義します。
- **Channel（チャネル）** は Provider 内の 1 つの上流エンドポイントです。上流タイプ、ベース URL、認証情報、モデル対応付け、重み、タイムアウトを保持します。

リクエストはまず Provider を選択し、その中の Channel を選択します。選択規則は[ルーティングと信頼性](/ja/docs/routing)を参照してください。

## Provider を作成

1. サイドバーの**プロバイダー**を開きます。
2. 作成ボタンをクリックして名前を入力します。
3. 既定値が合わない場合はリトライオプションを調整します。
   - `max_retries`：Provider 全体のリトライ総予算。`-1` はそのルート内で無制限。
   - `channel_max_retries`：次へ進む前の Channel 内リトライ回数。既定 `0`。
   - `channel_retry_interval_ms`：Channel 内リトライの間隔。既定 `0`。
4. 明確な理由がない限り、`circuit_breaker_enabled` は有効のままにします。

## Channel を追加

1. Provider を開き、**Channel を追加**をクリックします。
2. 上流タイプを選択します：`responses`、`chat_completion`、`messages`、`gemini`、`openai_image`、`replicate`。
3. 上流のベース URL と API キーを入力します。
4. 重みを設定します。トラフィックは対象 Channel 間で重みに比例して分配されます。既定 `1`。
5. 任意：Channel ごとの `proxy_url` を設定して、プロセスレベルの上流プロキシを上書きします。

後で Channel を編集するとき、API キー欄を空にすると保存済みのキーが維持されます。

## セッションキャッシュヘッダー

Channel で**自動セッションアフィニティ**を設定すると、転送する各リクエストに安定したセッション識別子を付けます。

この設定が `null` のとき、Monoize は次のベース URL で自動的に有効にします。

- Cloudflare Workers AI: `https://api.cloudflare.com/client/v4/accounts/{account_id}/ai`（任意の `/v1`）
- OpenCode Zen または OpenCode Go: `https://opencode.ai/zen` とその配下のパス

有効なとき、Monoize は同じ値で次の 2 つのヘッダーを送ります。

- `x-session-affinity`
- `x-opencode-session`

値の優先順位は次のとおりです。Channel の追加ヘッダーにある上記いずれかの名前、クライアントヘッダー（`session_id`、`session-id`、`x-session-id`、`x-opencode-session`、`x-session-affinity`）、本文の会話 ID、`prompt_cache_key`、最後に会話先頭のハッシュです。

OpenCode Go は `x-opencode-session` でプロンプトキャッシュをセッションに結びます。このヘッダーがないリクエストは失敗することがあります。

OpenCode Zen または OpenCode Go への生存プローブでは、Channel の追加ヘッダーにこれらの名前がないとき、リテラル値 `mono-probe` を送ります。

## Channel をテスト

Channel を開き、順次テストまたは同時テストを実行します。

テストは出力上限 16 token の短いストリーミング補完を送ります。HTTP 2xx だけでは不十分です。ストリームはプロトコルの終端イベントに到達する必要があります。

Responses Channel では、`response.completed` は合格です。error オブジェクトがない `response.incomplete` も合格です。推論モデルは 16 token 上限に達して `incomplete` を返すことがあります。その結果でも Channel には到達できています。

## モデルを対応付け

各 Channel は、提供する論理モデルを列挙します。モデルエントリの内容：

- `redirect`：実際の上流モデル名。空にすると論理名をそのまま送信します。
- `multiplier`：課金に使う非負の小数の価格乗数。`0` の場合、この Channel のリクエストは無料です。

Provider 内の有効な Channel が論理モデルを対応付けている場合のみ、そのモデルはその Provider にルーティングされます。

## リモート compact

モデル取得は、上流モデル一覧から Channel の compact 方式を分類します。

- `openai_compact_sibling`：一覧にベース ID と `{base}-openai-compact` の両方があります。それらの兄弟 ID を Channel のモデルマップに残してください。compact リクエストは回線モデルを兄弟モデルに書き換えます。
- `same_model`：そのような組はありません。compact リクエストは会話モデルをそのまま送ります。

上流一覧にない compact 兄弟 ID を作らないでください。

## 課金の上書きを設定

Provider で**価格未設定時の無料精算**と**Usage 欠落時の無料精算**を設定します。各設定は、グローバル値の継承、強制有効、強制無効を選べます。

ツール価格がない場合は常にフェイルオープンします。Monoize は未価格のツールクラスを記録し、そのクラスのツール料金をゼロにします。

## Provider の変換

Provider は順序付き変換ルールのリストを保持できます。Provider の選択後、上流エンコードの前に、その Provider が処理するすべてのリクエストに適用されます。[変換](/ja/docs/transforms)を参照してください。

## グループ

すべての Provider は少なくとも 1 つのグループに属します。API キーは、グループが交差する Provider のみにルーティングされます。ユーザー層や環境の分離にグループを使います。

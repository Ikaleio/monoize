## 概念

- **Provider** 是一個路由群組。它定義路由順序、重試預算、健康策略和有序的變換鏈。
- **Channel** 是 Provider 內的一個上游端點。它保存上游類型、基底 URL、憑證、模型對應、權重和逾時。

請求先選擇 Provider，再在其中選擇 Channel。選擇規則參見[路由與可靠性](/zh-TW/docs/routing)。

![Provider 列表](/images/en/providers.webp)

## 即時用量

每個 Provider 列顯示最近 60 秒的 RPM 和 TPM。頁面可見時每 10 秒更新一次。
RPM 統計所有使用者、所有終止狀態的已儲存請求。TPM 加總輸入與輸出 token，不重複計入快取或推理 token。
進行中的請求和重試鏈項目不計入統計。空時間窗顯示 `0`；指標無法取得時顯示 `—`。
每個 Provider 列顯示其位次和重試策略。每個 Channel 列顯示一個狀態、模型數量和權重占比。

## 建立 Provider

1. 在側邊欄開啟 **Provider**。
2. 點擊**新增 Provider** 並輸入名稱。
3. 預設值不合適時在**路由**分區調整重試選項：
   - **Provider 嘗試次數**：**嘗試全部可用 Channel**（預設，儲存為 `max_retries = -1`）或**指定次數** N（儲存為 `max_retries = N - 1`）。
   - `channel_max_retries`：切換前在單個 Channel 內的重試次數。預設 `0`。
   - `channel_retry_interval_ms`：Channel 內重試的間隔時間。預設 `0`。
4. 除非有明確理由，保持 `circuit_breaker_enabled` 開啟。

## 新增 Channel

1. 開啟 Provider 並點擊**新增 Channel**。
2. 選擇上游類型：`responses`、`chat_completion`、`messages`、`gemini`、`openai_image`、`openrouter_image`、`replicate`、`system_one` 或 `openai_decisions`。
3. 填寫上游基底 URL 和 API 金鑰。
4. 設定權重。流量按權重比例在符合條件的 Channel 之間分配。預設 `1`。
5. 可選：為單個 Channel 設定 `proxy_url`，覆寫程序層級上游代理。

之後編輯 Channel 時，API 金鑰留空則保持原有金鑰不變。

儲存無效的表單時，編輯器會開啟出錯的分區和 Channel，聚焦出錯欄位，並在欄位旁顯示錯誤。必填欄位標有**必填**。

## 決策模型

決策模型請使用 `system_one` 或 `openai_decisions` 類型的 Channel。這兩種 Channel 只服務 `/v1/systemone` 與 `/v1/decisions`。參見 [API 端點](/zh-TW/docs/endpoints)。

| 上游 | 類型 | 基底 URL |
| --- | --- | --- |
| TypeSafe Jev | `system_one` | `https://api.typesafe.ai` |
| OpenRouter | `system_one` | `https://openrouter.ai/api` |
| OpenAI | `openai_decisions` | `https://api.openai.com` |

Channel 測試會傳送一次只含一個是非題的非串流決策請求，可能產生上游費用。

## OpenRouter 圖片

OpenRouter 圖片模型請選擇 **OpenRouter Image**（`openrouter_image`）。
將基礎 URL 設為 `https://openrouter.ai/api`。
將邏輯模型映射至上游模型 ID，例如 `openai/gpt-image-2.5-sunburst`。

生成與編輯均呼叫上游 `/api/v1/images`。
Monoize 將輸入圖片轉換為 JSON `input_references`。
下游繼續使用 `/v1/images/generations` 和 `/v1/images/edits`。
此 Channel 類型不支援圖片遮罩與檔案 ID 引用。

取得模型功能讀取 OpenRouter 的圖片模型目錄。
Channel 測試會傳送一次非串流圖片生成請求，可能產生上游費用。
所選模型支援串流輸出時，轉送請求也支援串流輸出。
圖片編輯設為 `stream=true` 時，Monoize 會向 OpenRouter 傳送非串流請求，並維持下游 SSE。
等待期間傳送保活註解，取得圖片後傳送完成事件。

## 工作階段快取標頭

在 Channel 上設定**自動工作階段親和**，即可在每個轉送請求上送出穩定的工作階段識別碼。

該設定為 `null` 時，Monoize 對以下基底 URL 自動開啟：

- Cloudflare Workers AI：`https://api.cloudflare.com/client/v4/accounts/{account_id}/ai`（可選 `/v1`）
- OpenCode Zen 或 OpenCode Go：`https://opencode.ai/zen` 及其子路徑

開啟後，Monoize 用同一值送出這兩個標頭：

- `x-session-affinity`
- `x-opencode-session`

取值順序：Channel 自訂標頭中的上述任一名稱、用戶端標頭（`session_id`、`session-id`、`x-session-id`、`x-opencode-session` 或 `x-session-affinity`）、請求主體中的工作階段識別碼、`prompt_cache_key`，最後是工作階段開頭的雜湊。

OpenCode Go 用 `x-opencode-session` 將工作階段綁定到提示快取。缺少該標頭的請求可能失敗。

對 OpenCode Zen 或 OpenCode Go 的存活探測：當 Channel 自訂標頭未設定這兩個名稱時，送出字面值 `mono-probe`。

## Chat 方言

當**介面類型**為 **Chat Completion** 時，在「連線」中設定 **Chat 方言**。方言決定請求形狀：推理欄位、最大 Token 欄位、快取標記和 Provider 擴充。可選值為 `generic`、`openai`、`deepseek`、`openrouter` 和 `vercel`。參見 [Chat 方言](/zh-TW/docs/endpoints#chat-方言)。

- 新的 Chat Completion Channel 預設使用 `generic`。Monoize 不依 Base URL 或模型判斷方言。
- `chat_completion` Channel 省略 `chat_dialect` 或傳 `null` 時，API 保存 `generic`。未知值回傳 `400`，`param` 為 `channels[i].chat_dialect`。
- 其他類型的 Channel 傳非空 `chat_dialect` 時回傳 `400`。把類型從 Chat Completion 改成其他類型時，編輯器會清除該值。
- **協定覆寫**中的規則依模型 glob 選擇介面類型。規則選擇 **Chat Completion** 時，會顯示自己的 **Chat 方言**。對符合的模型，Monoize 以此值取代 Channel 方言。
- `chat_completion` 規則省略 `chat_dialect` 或傳 `null` 時，API 保存 `generic`。其他類型的規則傳非空值時回傳 `400`。未知值也回傳 `400`。兩種情況的 `param` 都是 `api_type_overrides[i].chat_dialect`。
- 新增此欄位的升級會把所有現有 Chat Completion Channel 和覆寫規則設為 `generic`。升級後，請為每個 OpenAI、DeepSeek、OpenRouter 或 Vercel Channel 選擇方言。

## 上游 WebSocket

在 **連線** 中、**介面類型** 之後設定 **上游 WebSocket**。不要把該控制項放在路由親和下。取值如下：

- `null`（未知）：Responses WebSocket 用戶端先嘗試 Upgrade。握手失敗時，同一 attempt 使用 HTTP SSE。僅當儲存值仍為 `null` 時，成功或失敗的握手可以寫入結果。
- `true`（支援）：優先 Upgrade。握手失敗仍使用 HTTP SSE。儲存值不變。
- `false`（不支援）：永不 Upgrade。

點選 **偵測 WebSocket** 以探測 `GET {base}/v1/responses`。結果寫入草稿。儲存 Provider 後才會持久化。HTTP POST 用戶端、健康探測與 Channel 存活測試仍走 HTTP。

## 測試 Channel

展開 Provider，在 Channel 列點擊**選擇模型測試**；或儲存後在 Channel 編輯器點擊**測試**。然後執行順序測試或並行測試。並行測試同時最多送出 5 個請求。關閉對話框後結果仍保留，進行中的測試會在背景繼續，點擊**停止**可取消。**重測失敗項目**只重跑失敗的模型。

展開 Provider 後，Channel 列的開關會立即啟用或停用該 Channel，無需開啟編輯器。

測試會送出一次短串流補全，輸出上限為 16 個 token。僅 HTTP 2xx 不夠。串流必須到達協定終結事件。

對 Responses Channel，`response.completed` 算通過。沒有 error 物件的 `response.incomplete` 也算通過。推理模型可能打滿 16 token 上限並回傳 `incomplete`。該結果仍表示 Channel 可達。

## 對應模型

要批次修改模型，在**支援的模型**中點擊**選取**，然後篩選清單、選取模型，再刪除或統一設定倍率。模型選擇器可以全選或清除目前結果。**手動新增**可一次輸入多個模型 ID。

每個 Channel 列出它服務的邏輯模型。模型條目包含：

- `redirect`：真實的上游模型名稱。留空則按邏輯名稱原樣送出。
- `multiplier`：用於計費的非負價格乘數。`0` 表示該 Channel 上的請求免費。

只有當 Provider 內至少有一個已啟用的 Channel 對應了某個邏輯模型時，該模型才會路由到這個 Provider。

## 遠端壓縮

擷取模型會根據上游模型清單判定 Channel 的 compact 方案。

- `openai_compact_sibling`：清單裡同時有基礎 ID 和 `{base}-openai-compact`。把這些兄弟模型留在 Channel 模型對應中。compact 請求會把線路模型改寫成兄弟模型。
- `same_model`：清單裡沒有這樣的配對。compact 請求按會話模型原樣送出。

不要編造上游清單中不存在的 compact 兄弟模型 ID。

## 設定計費覆寫項目

在 Provider 上設定**未定價時允許免費**和**缺少 Usage 時允許免費**。每個設定都可以繼承全域值、強制開啟或強制關閉。

缺少工具價格時一律按開放規則處理。Monoize 記錄未定價工具類別，並對該類別收取零工具費。

## Provider 變換

Provider 可以持有一組有序的變換規則。它們在 Provider 選定之後、上游編碼之前，作用於該 Provider 服務的每個請求。執行順序為 Provider → 全域 → API 金鑰，編輯器中也顯示此順序。參見[變換](/zh-TW/docs/transforms)。

## 群組

每個 Provider 至少屬於一個群組。API 金鑰只會路由到群組有交集的 Provider。用群組來區分使用者等級或環境。

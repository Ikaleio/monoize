## Logical models

Clients request a logical model name. Monoize resolves that name against your Providers and Channels. The name your clients see never has to match an upstream vendor name.

One logical model can map to several Channels across several Providers. This gives you failover and load splitting without client changes.

## Redirects

A Channel model entry can set `redirect` to the real upstream model name.

Example: clients call `my-fast-model`. Channel A redirects it to `gpt-4o-mini`. Channel B redirects it to `claude-3-5-haiku-20241022`. Billing and logs always show the logical name.

## Model pricing

The **Models** page is the pricing console. It has five tabs:

- **Model Pricing**: one price row per model. Each row sets a billing mode: `per_token`, `per_request`, or `tiered_expr`.
- **Unpriced Models**: mapped models that have no enabled price row.
- **Tool Prices**: prices for server-side tool classes. Units are `1k_calls`, `minute`, and `session`.
- **Upstream Sync**: price import from Models.dev, OpenRouter, or a new-api instance.
- **Group Pricing**: one billing ratio per group.

Monoize computes each charge in this order:

1. Compute the base charge from the model's price row and the recorded usage.
2. Multiply by the group's `billing_ratio`.
3. Multiply by the Channel model entry's `multiplier`.
4. Truncate to a whole number of nano-dollars.

A Channel `multiplier` of `0` makes requests on that Channel free.

Monoize resolves the redirected upstream model first. It falls back to the logical model only for a redirect without an upstream price.

Monoize multiplies the base charge by the Channel model `multiplier` and the routed group's `billing_ratio`. It records the final charge in nano-USD.

By default, Monoize rejects an unpriced model or a response without required Usage. Set the global free-settlement flags or a Provider override only when zero settlement is acceptable.

## Price sync

1. Open **Models → Upstream Sync**.
2. Select a source: Models.dev, OpenRouter, or a new-api instance.
3. Click **Preview**. The table shows new rows and changed fields.
4. Click **Apply**. Monoize writes the changes and records an audit row.

Sync does not change a locked field. Sync does not delete rows that you created manually.

## Model listing

`GET /v1/models` returns the logical models available to the calling API key. The result reflects key model restrictions and group membership.

## Model globs

Transform rules and some restrictions accept model glob patterns:

- `*` matches any sequence of characters, including an empty one.
- `?` matches exactly one character.
- Matching is case-sensitive and anchored to the full model name.

Example: `gpt-4*` matches `gpt-4o` and `gpt-4o-mini`. It does not match `o4-mini`.

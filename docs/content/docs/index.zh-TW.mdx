## 概述

Monoize 是以 Rust 撰寫的 AI API 閘道。它接受 OpenAI Responses、OpenAI Chat Completions、Anthropic Messages、Embeddings 與圖像格式的請求。它將請求轉發到設定的上游 Channel，並依客戶端使用的協議回傳回應。

Monoize 轉換協議語意，而不是替換 JSON 欄位名稱。它將每個請求解碼為統一的型別化內部表示，再編碼為選定的上游協議。回應沿同一路徑反向轉換。文字、推理、加密推理、工具呼叫、工具結果、圖像、用量與串流邊界在轉換中保持原有角色。

## 核心功能

- **協議轉換：** 支援使用任意受支援的下游端點呼叫任意設定的上游 Channel 類型。Monoize 在串流與非串流模式下轉換 Responses、Chat Completions、Messages、Gemini 與圖像協議。
- **路由與可靠性：** 一個邏輯模型可以匹配多個有序 Provider。每個 Provider 包含帶權重的 Channel。Monoize 重試可重試的失敗，前進到下一條路由，並在送出第一個回應位元組後停止備援。參見[路由與可靠性](/zh-TW/docs/routing)。
- **Transform 變換：** 33 個內建 Transform 可依 Provider、API 金鑰或全域範圍修改請求和回應。參見[變換](/zh-TW/docs/transforms)。
- **請求擷取：** 擷取功能預設關閉。開啟後，Monoize 會記錄每次上游嘗試的封包。結構化檢視器展示每一跳。參見[請求日誌](/zh-TW/docs/request-logs)。
- **儀表板：** 內嵌 Web 儀表板管理 Provider、Channel、模型、API 金鑰、使用者、計費與日誌。參見[儀表板](/zh-TW/docs/dashboard)。
## 支援的端點

| 方法 | 端點 | 協議 |
| --- | --- | --- |
| `GET` | `/v1/models` | OpenAI 相容模型列表 |
| `POST` | `/v1/responses` | OpenAI Responses，支援串流與非串流 |
| `GET` | `/v1/responses` | OpenAI Responses WebSocket 傳輸 |
| `POST` | `/v1/responses/compact` | Responses 壓縮 |
| `POST` | `/v1/chat/completions` | OpenAI Chat Completions |
| `POST` | `/v1/messages` | Anthropic Messages |
| `POST` | `/v1/embeddings` | Embeddings |
| `POST` | `/v1/images/generations` | 圖像生成 |
| `POST` | `/v1/images/edits` | Multipart 圖像編輯 |

每個轉發端點都另有 `/api/v1/...` 別名。

## 上游 Channel 類型

| 類型 | 原生上游協議 |
| --- | --- |
| `responses` | OpenAI Responses 相容 |
| `chat_completion` | OpenAI Chat Completions 相容 |
| `messages` | Anthropic Messages 相容 |
| `gemini` | Google Gemini 原生 |
| `openai_image` | OpenAI 相容圖像 API |
| `replicate` | Replicate predictions |

## 限制

- Monoize 轉發工具定義和工具呼叫，不在本地執行工具。
- Monoize 不提供 OpenAI Files、向量儲存或本地檢索。
- 送出第一個下游位元組後備援即結束。Monoize 不會在活動串流中途切換 Provider。
- 跨協議族轉換保留受支援的語意。沒有目標表示的 Provider 專用巢狀欄位會被移除。
- 圖像壓縮預設關閉。除非設定 `image_resolve_urls` Transform，Monoize 不會抓取遠端圖像 URL。

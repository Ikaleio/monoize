## ベース URL と認証

リクエストは Monoize のリッスンアドレスに送信します。デフォルトは `http://localhost:8080` です。API キーは次のいずれかのヘッダーで送信します。

```bash
Authorization: Bearer sk-...
# または
x-api-key: sk-...
```

以下の各エンドポイントには `/api` プレフィックスの別名があります。例: `/api/v1/chat/completions`。クライアントが `/api` パスを固定している場合に別名を使います。

どのエンドポイントも任意の上流タイプに到達できます。たとえば、クライアントが `/v1/messages` を呼び出し、ルートが `chat_completion` タイプの Channel でそのモデルを提供する構成が可能です。Monoize は双方向でプロトコルを変換します。

Chat ルートは、空の内容を持つ OpenRouter の `configuration_update` メッセージも保持します。ファイルの data URI を Messages 文書に変換するときは MIME タイプを保持します。Messages ストリームは `citations_delta` の引用を保持します。Responses のコンテンツフィルターによる終了は未完了として扱い、長さの制限として報告しません。

Chat と Responses は、対応する URL 引用を対象形式に変換します。変換できない引用位置は元のプロトコル内で保持します。Token logprobs は対応するテキストに関連付けます。テキストの変更後、一致しない確率情報は破棄します。Responses の失敗時の最終状態には、部分出力、使用量、エラーの詳細を保持します。Chat と Messages は失敗またはキャンセルをエラーとして返します。Messages は一時停止、圧縮、コンテキスト上限の停止理由を保持します。課金には報告されたすべての圧縮イテレーションを含め、主生成の使用量を二重計上しません。

プロトコル変換では、raw 推論、読み取り可能な要約、不透明な再送ペイロードを区別します。raw 推論を削除しても、要約から復元しません。Messages の thinking テキストは要約として扱い、signature は不透明な値として保持します。不正なストリーム順序や形式が不正な既知イベントはエラーになります。完全な Messages リクエストとレスポンスでは、途中で切れたツール JSON を拒否します。ネイティブの max_tokens ストリームでは、未完成の引数バイト列を保持できます。

Chat の推論断片は、安定した識別子が同じ場合、同じノードに蓄積します。最終スナップショットでは未送信の接尾部だけを追加します。独立した detail は分離して保持します。

ツール引数は完了前に送信できます。ツール署名エンベロープはツールの完了値が確定してから送信し、署名を一つの不透明な値として保持します。

Messages リクエストでは、オブジェクト型の `input_schema` を持つ custom ツール、JSON オブジェクトの呼び出し引数、関連する結果をまとめて変換します。`call_id` は保持します。無効な schema や引数はエラーになります。

Responses オブジェクトに null 以外の error があり、有効な status がない場合はエラーになります。空のオブジェクトは拒否します。エラーがなく output 配列を持つ互換レスポンスでは、status を省略できます。


レスポンスは、呼び出したキーが利用できる論理モデルを OpenAI のリスト形式で返します。

## Chat Completions

```bash
curl http://localhost:8080/v1/chat/completions \
  -H "Authorization: Bearer sk-..." \
  -H "Content-Type: application/json" \
  -d '{
    "model": "my-model",
    "messages": [{ "role": "user", "content": "Hello" }],
    "stream": true
  }'
```

`"stream": true` を設定するとサーバー送信イベントを使います。省略または `false` にすると単一の JSON レスポンスを返します。

## Responses

```bash
curl http://localhost:8080/v1/responses \
  -H "Authorization: Bearer sk-..." \
  -H "Content-Type: application/json" \
  -d '{
    "model": "my-model",
    "input": "Hello",
    "stream": true
  }'
```

補足:

- 返された Monoize id を `previous_response_id` に指定すると、任意の上流プロトコルで応答を継続できます。履歴は API Key ごとに分離されます。
- HTTP 履歴の既定値は `store=true` です。現在のプロセスで最大 30 分間保持します。再起動やキャッシュの退避で記録は削除されます。
- `store=false` を指定すると HTTP 履歴を保持しません。不明または期限切れの id は `400 previous_response_not_found` を返します。その場合は履歴全体を再送してください。
- 毎回、現在の instructions と制御パラメーターを指定してください。前回のトップレベル `instructions` は継承されません。
- `GET /v1/responses` は Codex WebSocket v1 と v2 に対応します。v1 は `response.done`、v2 は `response.completed` を送信します。`store=false` でも接続内の継続は利用できます。
- Responses WebSocket クライアントは Responses Channel に対して上流 WebSocket を開くことがあります。`POST /v1/responses` は HTTP のままです。ハンドシェイク失敗時は、同じ attempt で HTTP SSE に戻します。
- `POST /v1/responses/compact` は会話をコンパクト化します。
- Monoize はネイティブの compact ボディを上流の `POST /v1/responses/compact` に転送します。
- Channel 選択後、その Channel が `{model}-openai-compact` をマップしていれば、Monoize はその兄弟モデルを回線モデルとして送ります。そうでなければ会話モデルを送ります。
- 課金は会話モデルの価格を使います。兄弟モデル ID に別の価格行は不要です。

Responses 上流へのリクエストでは、Monoize は明示された `include` と `reasoning.summary` の値を保持します。`reasoning.encrypted_content` や既定の要約設定は自動で追加しません。

## 推論を無効にする

Chat Completions リクエストでは `"reasoning_effort": "none"` を設定してください。Responses リクエストでは `"reasoning": { "effort": "none" }` を設定してください。

Monoize は明示的な `none` を OpenAI 互換の上流に送信します。Chat のネイティブ `reasoning` オブジェクトがある場合、その中に `effort: "none"` を設定し、最上位の短縮フィールドは送信しません。

Messages の制御パラメーターが明示されていない場合、Monoize は Messages 上流に `thinking: { "type": "disabled" }` を送信します。Gemini 上流には `generationConfig.thinkingConfig.thinkingBudget: 0` を送信します。

DeepSeek Chat リクエストでは推論努力の値をそのまま転送します。値の再マッピングや `thinking` 制御パラメーターの自動生成は行いません。

推論の強度を省略すると、上流のデフォルト値が使われます。推論の無効化に対応するモデルを選択してください。推論が必須のモデルでは無効化できません。

## Gemini 上流

Channel の上流タイプを `gemini` に設定すると、既存のエンドポイントから Gemini を利用できます。この対応には、公開 Gemini HTTP エンドポイントの追加や Live API は含まれません。

Monoize は `generateContent` のリクエスト、レスポンス、会話履歴を双方向に変換します。ストリーミングには `streamGenerateContent` SSE を使います。

- テキスト、推論、関数呼び出し、関数の結果、対応するメディアは、順序と識別情報を保持します。思考署名は元の Part との対応を保持します。
- 生成パラメーター、構造化レスポンス形式、ツール、ツール選択を、変換先が対応するフィールドに変換します。
- Token logprobs は一致するテキストに関連付けられます。テキストが変わると、無効になったスコアを破棄します。Gemini で要求できる top logprobs は最大 20 個です。
- 表現可能な引用と grounding の参照リンクを変換先の形式に変換します。引用範囲は、非 ASCII テキストを含めて元の位置を保持します。
- テキストと推論は完了前から順次出力します。完全な内容が必要なメディアや署名付き Part は、完了まで待つ場合があります。失敗または途中終了したストリームはエラーを返します。
- Monoize は index が 0 の候補を優先し、なければ最初の候補を返します。独立した候補は結合しません。

Gemini 専用ツール、Provider が実行するコード、変換できないメタデータは Gemini 内でのみ保持します。変換先のプロトコルには、表現可能な機能だけを送信します。

## 画像

生成:

```bash
curl http://localhost:8080/v1/images/generations \
  -H "Authorization: Bearer sk-..." \
  -H "Content-Type: application/json" \
  -d '{
    "model": "my-image-model",
    "prompt": "A lighthouse at dawn",
    "size": "1024x1024"
  }'
```

画像ファイルのアップロードには `multipart/form-data` を使います。

```bash
curl http://localhost:8080/v1/images/edits \
  -H "Authorization: Bearer sk-..." \
  -F model="my-image-model" \
  -F prompt="Add a red boat" \
  -F 'image[]=@input.png'
```

PNG マスクを使う場合は `-F mask=@mask.png` を追加します。編集リクエストには 1〜16 枚の元画像と、最大 1 個のマスクを指定できます。

画像の参照を送る場合は JSON を使います。

```bash
curl http://localhost:8080/v1/images/edits \
  -H "Authorization: Bearer sk-..." \
  -H "Content-Type: application/json" \
  -d '{
    "model": "my-image-model",
    "prompt": "Add a red boat",
    "images": [{ "image_url": "https://example.com/input.png" }],
    "mask": { "image_url": "https://example.com/mask.png" }
  }'
```

各 `images` 要素と任意の `mask` オブジェクトには、`image_url` または `file_id` のどちらか一方だけを指定します。`image_url` は HTTP(S) URL と Base64 データ URL に対応します。ファイル ID は、選択した上流の認証情報でアクセスできる必要があります。ファイル ID によって上流アカウントや Provider 間でファイルを転送することはできません。

両エンドポイントで `model` と `prompt` が必要です。非ストリーミングの `n` は、従来どおり独立したサブリクエストに分割します。画像 SSE イベントを受け取るには `stream=true` と `n=1` を指定します。ネイティブの `openai_image` ルートはインライン画像を multipart で送信します。入力またはマスクに HTTP(S) URL やファイル参照が残る場合は JSON を使います。

`stream=true` を指定すると、Monoize は直ちに SSE ハートビートコメントを送ります。データイベントが 15 秒間ない場合は再送します。OpenRouter の画像編集には非ストリーミングの上流リクエストを自動で使用します。ほかのルートでは、ストリーミングを明示的に拒否する HTTP 400 または 422 に対して一度だけ非ストリーミングで再送します。JSON の画像レスポンスは完了イベントに変換し、プレビュー画像は合成しません。課金とログは 1 回のストリーミングリクエストとして処理します。通常のネットワークエラーはこの再送の対象外です。生成中の下流接続を維持できますが、上流リクエストのタイムアウトは延長しません。

Responses ルートでは [image_enable_openai_generation_tool](/ja/docs/transforms/image_enable_openai_generation_tool) を設定します。リクエストの画像設定が変換のデフォルト値より優先され、マスクはツールの `input_image_mask` に変換されます。画像の `background` はツールの設定です。Responses の真偽値 `background` とは別に扱います。Responses ルートは画像の `style` と `response_format="url"` を明示的なエラーで拒否します。

画像レスポンスは、上流が返した `quality`、`size`、`background`、`output_format`、画像の `model` を保持します。上流が返さない値は省略します。リクエストの値を実行結果として補完しません。複数の画像では、すべての画像が同じ値を報告したフィールドだけをトップレベルに返します。画像ストリームの完了イベントは、その画像のメタデータを返します。

## 公式 SDK の利用

公式 SDK のベース URL を Monoize に向けます。

```python
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:8080/v1",
    api_key="sk-...",
)
```

```python
import anthropic

client = anthropic.Anthropic(
    base_url="http://localhost:8080",
    api_key="sk-...",
)
```

## エラーレスポンス

| HTTP ステータス | コード | 意味 |
| --- | --- | --- |
| `401` | `unauthorized` | API キーが未指定、無効、無効化済み、または期限切れ |
| `402` | `insufficient_balance` | ユーザーまたはサブアカウントの残高が不足 |
| `403` | `model_not_allowed` | キーのモデル制限が要求モデルを拒否 |
| `403` | `ip_not_allowed` | クライアント IP がキーの IP ホワイトリストにない |
| `502` | `upstream_error` | モデルを提供するルートがない、または適格なルートがすべて失敗 |

上流のエラーテキストはクライアントに届く前にサニタイズされます。完全な詳細は[リクエストログ](/ja/docs/request-logs)で確認できます。
